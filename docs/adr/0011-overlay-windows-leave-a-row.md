# 覆盖窗口不盖满整台显示器：让出最下面一行，拖到边上时选区补满

截图框选窗口和钉图菜单窗口原本铺满整台显示器；Wallpaper Engine 在每次截图时黑一下（[#230](https://github.com/Yukk1No/kinshoko/issues/230)）。本机实测 `SHQueryUserNotificationState`：只要有**一个**窗口整个盖住某台显示器，Windows 就报 `QUNS_BUSY`（有全屏程序在跑），与窗口是否置顶、是否在前台无关；比显示器矮一行就不报，两个窗口拼起来盖满也不报。框选窗口和菜单窗口显示期间都报 `QUNS_BUSY`，隐藏后恢复。Wallpaper Engine 等程序在“有全屏程序”时暂停或停止，黑一下由此而来；本机没有装它，这一环由维护者在新 beta 上确认。

决定：Kinshoko 所有盖住显示器的覆盖窗口（钉图层、钉图菜单、截图框选）都用同一个矩形 `overlay_window`：整台显示器让出**最下面一行**物理像素。钉图层从 #193 起已经这样做，这次改为共用并推广到另外两个窗口。

框选仍以整台显示器为准：冻结屏幕是整台显示器，选区坐标相对显示器。框选窗口少了最下面一行，那一行显示的是窗口下面的实时画面（通常是任务栏的边），指针在那一行上按下也落到下面的窗口。为了让这一行照样截得到：拖动时选区的右、下边离显示器边缘不到 2 个物理像素就补到边缘，超出显示器的部分夹回显示器里（`reachEdges`）。拖动有指针捕获，指针移到最下面一行时页面仍收到坐标。这同时补上了一个旧缺口：选区不含指针所在的那一列和那一行，而指针最多到最后一个像素，所以以前最右一列、最下一行本来就选不到。

## Considered Options

- **让出最上面一行或某一侧的一列**：效果一样，但钉图层早已让出最下面一行。最下面一行通常是任务栏的边，截图里最少用到，所以三个窗口统一让最下面一行。
- **框选窗口拆成两个窗口拼满**（主体少一行，再加一条一行高的窗口画最后一行）：冻结画面完整、最后一行也能按下。但要多管一个窗口的显示、隐藏、跨显示器移动、指针捕获和交接，换来的只是能从最后一行**开始**拖。不值得。
- **只改菜单窗口，框选窗口保持全屏**：截图本来是短暂的全屏操作；但 F1 时 Wallpaper Engine 仍会黑一下，没有解决 #230。
- **换掉覆盖窗口的截图方式**：选区必须画在冻结画面上，任何实现都需要窗口盖住整个显示器（或拼起来盖住），没有不覆盖的做法。
- **在 Kinshoko 里检测并排除自己**：只能管 Kinshoko 自己的逻辑（例如“有全屏程序时暂停打标”可以排除自己的窗口），管不了 Wallpaper Engine 等别的程序。

## Consequences

- 选区的右、下边在离边缘 2 个物理像素以内时只能是边缘本身：不能精确停在倒数第一、二行或最后一列。框选本来就是粗定位，可以接受。
- 不能从最下面一行开始拖动；从下往上拖时起点最低在倒数第二行，靠补满规则仍能包含最后一行。
- 框选时在最下面一行上单击会点到下面的窗口（例如任务栏按钮），框选窗口失去焦点但不结束。任务栏设为自动隐藏时，指针停在最下面一行可能把它唤出，盖在冻结画面上；这一点没有实测，有人反馈再处理。
- 钉图菜单的锚点夹在窗口里：在显示器最下面一行右键，菜单从上一行弹出。
- 几何一律按物理像素，与缩放比例无关：150% 缩放下让出的一行只有 2/3 个 CSS 像素。多显示器时每台显示器各自让出自己最下面一行；拖到下方或旁边的另一台显示器上时，选区夹回框选所在的显示器。
- 以后新增盖住显示器的窗口，一律经 `overlay_window` 取矩形，不能直接用显示器矩形。
