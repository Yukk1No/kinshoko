# 占位图存进资料库 SQLite；工作区长期只读打开每个登记的资料库

图片墙首屏慢（#288、#313）的两处结构性开销：p32 占位图逐个存成文件，浏览一页要逐个查找、打开、读取；每个 `thumb://` 请求都把所有登记的资料库只读重开一遍，再排队等登记表、标签目录、工作区三把全局锁核对。

决定：

- **p32 存在资料库的 `placeholder` 表里**（按原图字节的 SHA-256 一行，带管线版本、内容类型和字节），浏览一页按显示用的来源每库一条查询读出。导入时写库，打开资料库时后台补齐也写库；#313 之前的 `<sha>-p32.<webp|png>` 文件由补齐读进来后删掉。占位图仍是可重建的替身（[ADR 0010](0010-stand-in-fidelity.md)）：这些写入不等落盘（`synchronous=NORMAL`），断电丢掉的下次打开补齐。正式缩略图仍是缓存目录里的文件。
- **工作区为每个登记的资料库保留一个长期只读句柄**（`ImageGate`），快照、结果与目录都用它；每次取到的快照发布给缩略图请求。缩略图请求只在登记表、安全模式范围、每个库的修订号都与发布的快照相同时按快照放行，否则走原来的加锁路径。句柄身份按数据库文件标识判断。

## Considered Options

- **占位图文件并行读**：只是止痛；p32 只有几百字节，每个文件的打开、杀毒扫描和至少一个 4 KB 簇都比数据本身大一两个数量级。
- **首屏先不带占位图、随后补发**：图片墙先闪一片空白。
- **缩略图请求不核对、只信前端**：被封印的图可能经旧地址给出，不可接受。

## Consequences

- 加了一次资料库迁移：和以往的迁移一样，还没用新版本打开过的资料库只读打开时报“需要先在 Kinshoko 中打开一次以完成升级”。
- Windows 上 SQLite 打开的文件不允许删除或改名：应用开着时，**每个**登记的资料库（之前只有正在整理的那个）的文件夹都改不了名、移不走，移动盘“安全弹出”也会提示占用。切换资料库、取消登记、整份恢复设置时放掉这些句柄；直接拔掉移动盘不受影响（读失败的句柄丢弃，下次重开）。
- 被封印的图仍绝不给出：快照与修订号对不上就走加锁路径，读完文件按修订号与安全模式代次复核。
