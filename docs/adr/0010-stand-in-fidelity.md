# 替身只要求内容和几何一致，颜色允许小偏差；正式派生图仍守 ADR-0005

#165 给整图解码加了按内存的全局限流，缺缓存时缩略图要排队生成（[#168](https://github.com/Yukk1No/kinshoko/issues/168)）。维护者的原则：只显示一两秒、随后一定被换掉的图可以低精度，画师会长期端详的图才需要高精度。据此，图按**显示角色**分两类，与是否写入缓存无关：

- **正式派生图**：缩略图档位、`fit-<像素>`、`full` 等画师最终看到并据此判断的图，继续遵守 ADR-0005（`moxcms` 色彩解释、f32 预乘 alpha 缩放），还原度门槛为最差色块 ΔE2000 < 1。
- **替身**：正式派生图就绪前临时顶上、就绪后一定被换掉的图。p32 占位图（#110）、查看器连续缩放时的替身（#128），以及缺缓存时的低精度预览（#168）都属于这一类。

替身的规则：

- 内容和几何必须与正式派生图一致：同一张图、同样转正、同样宽高比。不设阈值。
- 分辨率和缩放可以降低，例如放大已缓存的更低一档派生图、JPEG 按 1/2、1/4、1/8 做 DCT 缩小解码。
- 颜色允许小偏差：与正式派生图相比最差色块 ΔE2000 ≤ 3，用还原度门槛实验的同一组样本测。这个偏差在模糊加淡入的替换过程中看不出跳变；跳过色彩管理把广色域或 CMYK 当 sRGB 的做法通常远超 3，由阈值自然排除。
- 降精度的来源要先换来明显的速度：同一组样本上，生成到可显示的耗时至少比忠实来源少一半，否则不引入偏差。
- 替身不写入正式派生图的缓存位置，任何读正式派生图的路径都不会读到替身。
- 不设显示时长上限，但必须最终被替换：卡片挂载期间，它的正式派生图请求只排队、不取消；正式派生图生成失败时撤掉替身，显示失败或中性状态，不让替身冒充结果留在屏幕上。
- 离开应用的产出（复制、导出、拖出、收藏）只用正式派生图或原图，不用替身。
- 截图框住正在显示替身的参考图时，同样映射回原图像素，不取屏幕上替身的像素：参考图能否作为截图来源，不取决于它的正式派生图是否已经显示出来。

## Considered Options

- **按存储方式划分（写不写缓存）**：p32 写入缓存却从不被端详，这样划分会把它错归为正式派生图，所以按显示角色划分。
- **替身的颜色必须与正式派生图一致**：最稳妥，但替身本来就既不清晰也没缩准，画师拿它做不了判断；为颜色付出整图色彩管理的代价，与替身“尽快给出”的目的相反。
- **原图内嵌的 EXIF 缩略图**：最快，但原图修改过之后内嵌缩略图可能还是旧内容，方向和色彩声明也可能和原图对不上。这是内容和几何的问题，不是颜色问题，所以不论快多少都不用。
- **GPU 解码或缩放**：传输开销、颜色一致性的验收和驱动兼容性，成本都高过收益，暂不考虑。

## Consequences

- p32 保留，作为所有替身的兜底：它嵌在浏览页里、不进限流队列，是卡片出现时唯一能立刻显示的图。导入时仍走完整管线顺带生成；打开资料库时的后台补齐排在生成队列的最低一档，可以用 JPEG 缩小解码。
- 生成队列按可见性排序：视口内 > 挂载范围内 > 预取 > p32 补齐。卡片离开挂载范围时取消还没开始的请求，已经开始的做完并写入缓存。
- 持久化路径上能不能用 JPEG 缩小解码（先解到不低于目标 2 倍、再走 f32 缩放），仍以 ΔE2000 < 1 的门槛和逐像素差异报告为准，由维护者看数据决定，本决定不放宽正式派生图。
