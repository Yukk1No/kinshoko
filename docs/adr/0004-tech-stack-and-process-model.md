# 以 Tauri 2 常驻进程承载应用，自动标签在子进程中运行

首版要同时替代 Eagle 与 Snipaste，截图和钉图必须随时可用，所以 Kinshoko 是一个常驻托盘的 Tauri 2 + Rust 进程，前端为 React／TS；关闭主窗口只销毁其 WebView，钉图、截图与全局快捷键留在同一进程。自动标签不在这个进程里跑，而是由同一个 exe 以子命令启动独立子进程：DirectML 显存溢出或驱动崩溃不会带走桌面钉图，画师开始绘画时可以直接结束子进程立刻归还显存。依据是 #7 的 Tauri 钉图原型、#13 的 React 浏览样稿与 #6 在画师 4 GB 显卡上的打标探测（[#9](https://github.com/Yukk1No/kinshoko/issues/9)）。

## Considered Options

- **Qt 6／PySide6**：#5 核查时保留为候选，但没有任何原型证据；界面样稿、字体方案和钉图原型都建立在 WebView2 上。
- **打标在主进程内调用 `ort`**：少一层进程间通信，但推理崩溃或显存溢出会拖垮常驻的钉图。
- **拆成常驻的钉图进程与按需启动的主程序**：两套窗口与状态同步，收益只是常驻内存略小。

## Consequences

- 打标模块与子进程之间是一个真正的接缝：生产用子进程 adapter，测试用内存 adapter。
- 常驻进程的内存占用要在无独显机器上实测；主窗口的 WebView 按需重建。
