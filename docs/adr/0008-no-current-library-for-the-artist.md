# 画师不再需要“当前资料库”，后端仍是单一写入者、按需切换

#78 之后侧栏同时列出所有资料库，但只有“当前资料库”的目录可以整理，切换靠侧栏标题的下拉框；画师要先选“当前”再整理，导入的保存目标却又是另外明确选择的（见 GLOSSARY 的保存目标）。人工验收反馈 9 认为这两个概念让侧栏难懂。决定：界面上不再有“当前资料库”，画师直接整理任何一个可用资料库；后端仍然只为一个资料库开可写句柄，画师整理哪个库就按需把可写句柄切过去，遇到该库正有导入收尾时等它结束再执行，并给轻提示。

## Considered Options

- **后端同时开多个可写资料库**：最彻底，但缩略图协议、导入回执与自动打标子进程都按“活动资料库”归属，需要逐一改成按库归属；改动大且难回退。等到确实需要同时向两个库导入、或按需切换的等待让画师感到卡顿时再重开。
- **保留“当前资料库”，只改界面**：概念仍在，反馈 9 的问题没有解决。

## Consequences

- “活动资料库”只是后端实现细节，不出现在文案、术语和工单标题里（GLOSSARY：浏览范围，_Avoid_ 当前资料库）。
- 侧栏的回收站跟随所选浏览范围的资料库；选“全部图片”时显示各库合计。
- 依赖活动资料库的入口（缩略图协议、安全模式开关、导入事件）在切换时不能让另一个库的界面状态串台；验收要覆盖“A 库导入中，整理 B 库文件夹”。

## 修订：自动打标覆盖所有资料库，不跟活动资料库走（#414，2026-11-03）

订阅在后台把作品存进它的保存目标，目标库不会变成活动资料库；自动打标只跟着活动资料库，这些图就一直不打标，设置里的打标状态却只看活动库、显示已全部完成。为了让整个软件的图都能按自动标签查找，改为：

- 后端可以同时为多个资料库持有可写句柄（保存目标早已如此），同一个资料库始终只有一个句柄。活动资料库只决定缩略图协议、导入事件这类与界面有关的转发去向。
- 自动打标是全设备一个调度：同一时间只有一个打标子进程，画师正在整理的库先打，其余按登记顺序轮流。调度器空闲时自己去各库找未打标的图，写入方不必通知它也不会漏；写入后叫醒它只为早点开始。
- 设置里的打标状态合计所有资料库；有库暂时打不开、未打标数不明时，不显示已全部完成。
