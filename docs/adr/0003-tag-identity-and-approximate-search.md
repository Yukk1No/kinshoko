# 标签身份、外部对应与近似查找

标签以库内稳定的 `tag_id` 为身份，打标模型的 Danbooru 名称等外部词表名称只作为标签的外部对应：画师添加的标签、pixiv 角色名与复合标签、Eagle 原有标签和作者都没有 Danbooru 名称，以外部名称为身份就容纳不了它们，换用其他词表的模型时也会对不上。标签名按语言保存，显示随界面语言；随软件分发的翻译表只在标签首次进库时提供各语言的初始名称与别名，之后名称属于画师的整理数据。没有翻译的外部名称照常进库，界面标明尚未翻译，不丢弃模型结果。

蓝瞳与水色瞳算不算一回事没有客观答案，所以资料库内的标签不合并，粒度跟随外部词表；相近与否只在查找时决定。近似查找把相近标签展开成可见、可改回精确的任一条件，每张参考图仍按自己的标签记录。展开有两种来源，用户二选一：随软件维护、离线可用的近似对应表（默认）；或 JEV 远端 API，由用户自行填写 API key 开启，开启时说明会发送查找词与当前库的标签名，安全模式开启时不发送成人内容相关标签，不可用时退回近似对应表。JEV 实测准确度达标后优先于近似对应表。近似对应表按外部对应写成，Eagle 导入向导可以为没有外部对应的标签补上对应，让它们参与近似查找。

## Considered Options

- **以 Danbooru 名称为标签身份，翻译表做显示**：I18N 简单，但上述没有外部名称的标签无处安放。
- **同义合并为一个标签**：粒度一旦合并，合并后人工添加的标签无法再拆开；不同画师对“相近”的边界也不同。
- **上下位蕴含**（低双马尾蕴含双马尾）：改变排除条件的语义，暂定，可能由近似查找代替。

## Consequences

- 合并资料库时把两库中的同一个标签对应起来（优先按外部对应，其次按名称）不是这里否定的标签合并，仍按[数据与存储模型](../discovery/data-storage-model.md)的合并向导处理。
- 模型原始结果按外部名称保存，近似对应表与翻译表更新不改动已有的人工决定。
