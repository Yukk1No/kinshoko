# 应用统一标签身份与资料库内对应

规格 #78 的跨库查找要求同一标签在不同资料库中使用统一身份。应用持久维护统一标签目录；资料库继续保存原图、来源事实、文件夹及逐图人工标签决定。每个库内标签 ID 显式对应一个统一身份，身份不依赖标签名称或外部词表值。命名空间属于身份。相同命名空间和明确外部对应可以建立共同身份；只有名称或别名重合时保持独立，使用者可以检查、纠正对应或拆成独立身份。

本决定自 #78 增量起替代 ADR-0003 中“标签以库内稳定 tag_id 为身份”及“名称属于资料库整理数据”的跨库适用方式。ADR-0003、#42、#71 和历史验收记录继续描述其原有范围，不修改原文、不回算完成状态。库内 ID 仍稳定有效，人工标签决定仍以其本地 ID 保存；应用纠正对应不重写这些决定。

首次接入旧库时保存标签定义与原显示文字，并标记名称来源待处理。这些文字不因登记顺序成为用户的全局名称偏好。名称默认、显式偏好和迁移选择由 #78 的后续名称工单实现。外部对应使用词表名称和值，并与命名空间一起解析；它们不是显示别名，也不是稳定身份。旧格式外部对应明确解释为 Danbooru 词表，保留兼容入口。

## Considered Options

- 继续用库内 ID 充当应用身份：两份独立库的 ID 不同，无法表达跨库对应。
- 按名称或别名自动合并：同名异义和别名歧义会混合人工整理结果。
- 仅建立可重建的显示缓存：纠正后的对应和未来全局名称偏好会随重建丢失。

## Consequences

统一目录是应用持久数据。资料库和参考组包需要携带解释标签的定义依赖；内容迁移、名称迁移、备份及恢复的具体动作由 #78 后续工单接入。核心公开动作不依赖 Tauri；命令层转发动作，保留现有库内 ID 调用方式。
