# 钉图到显示器的颜色转换由 Rust（moxcms）和着色器查表完成，钉图只显示派生图

修订 [ADR 0005](0005-two-path-display-pipeline.md)。0005 规定到屏幕的颜色转换只有 WebView2 一处。钉图改成 wgpu 画的原生窗口以后（[ADR 0013](0013-native-pin-windows-wgpu.md)），钉图的像素不再经过 WebView2，这一处转换必须移到 Rust。

决定：**看图界面仍由 WebView2 转换到显示器；钉图由 Rust 转换。** 钉图只显示 Rust 生成的派生图：按显示尺寸取 `fit-<像素>` 档，放到 1:1 及以上用 `full`（原图，或 0005 规定的原尺寸 `sdr` 派生图），不再把原图交给别的解码器。上传时用 moxcms 把派生图从它的色彩声明转到线性工作空间（线性 sRGB 原色、扩展范围，`Rgba16Float`），GPU 的插值因此都在线性光下。着色器最后一步查一张 3D LUT，由 moxcms 按“线性工作空间 → 钉图所在显示器的配置文件”生成，输出显示器编码。钉图拖到配置文件不同的显示器上只换 LUT，不重新上传。截图钉图的源图按截图时那台显示器的配置文件标注：回到同一台显示器时 LUT 为恒等，与截取时屏幕逐像素一致；到别的显示器时按两者的配置文件转换。

依据：[跨平台 GPU 方案调研 · 颜色](../discovery/pin-gpu-design/shell-and-modules.md#5-颜色设计没有实测)。颜色部分是设计，原型只做了 sRGB，没有实测。

## Considered Options

- **钉图里继续用 WebView2 或 Chromium 的颜色解释**：钉图已经不是 WebView，做不到；用 skia 换来与 Chromium 同源的解释，代价见 ADR 0013。
- **上传前一次转换到显示器空间、8 位上传**（ULW 原型的做法）：每帧不再转换，但插值在显示器编码下做，不在线性光下；换显示器要重新转换整张图（24 MP 约 55 ms）；HDR 没有路。
- **上传原图的原始编码、着色器里做完整的 ICC 转换**：查找表型 ICC、CMYK 要在着色器里实现，等于再写一个色彩管理模块；派生图已经由 moxcms 解释过，没有必要。

## Consequences

- 到屏幕的颜色转换从一处变成两处：看图界面（WebView2，skcms）和钉图（moxcms＋LUT）。门槛实验（`fidelity_gate`）增加“钉图 vs 查看器 1:1”：同一组样本，在普通 SDR 显示器、未开自动色彩管理、装校准 ICC 时，最差色块 ΔE2000 < 1，与正式派生图的门槛相同。广色域、CMYK、查找表型 ICC 的样本都在其中。
- 钉图 100%、未旋转翻转时，sRGB 图在 sRGB 显示器上与派生图逐像素相同（8 位值）；离屏渲染测试守住这一条。
- 手势中由 mip 缩放出的画面是 ADR 0010 意义上的替身（内容和几何一致，颜色与正式派生图同一张 LUT），停手后换成精确尺寸的派生图。遮蔽时仍只取 64 px 的派生图。
- 自动色彩管理或 HDR 显示时，交换链改为 scRGB `Rgba16Float`，LUT 换成恒等或色调映射；这一路 v1 只保证与看图界面在 ACM 下同样被限制在 sRGB 内、不比现在差，HDR 钉图另议。0005 里“HDR 显示时把钉图渲染器换成 WebGPU”的设想由此落空，改由本决定的 scRGB 出口承担。
- 显示器配置文件变化（换显示器、改校准、开关 ACM）时重新生成 LUT；读配置文件属于平台层，LUT 的生成与平台无关。
- 诊断信息除 WebView2 的色彩状态外，还要写出钉图所用的 GPU 适配器、交换链格式和每台显示器的配置文件名。
