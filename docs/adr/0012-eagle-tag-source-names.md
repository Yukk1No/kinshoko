# Eagle 原有标签的叫法是资料库的来源名称，语言按文字判断

beta1 反馈 [#217](https://github.com/Yukk1No/kinshoko/issues/217)：迁入 Eagle 后标签“全是英文”。原因是 Eagle 原文一律记成简体中文名称，迁入向导即使把 `blue eyes` 对上外部对应 `blue_eyes`，这个“中文名称”仍压着默认名称“蓝瞳”；英文原文占着中文名称，也破坏 I18N。

决定：Eagle 原有标签的叫法是**来源名称**：属于那份资料库的来源层，按 ADR 0001 重新迁入时跟随 Eagle 更新，从不回写 Eagle。单库内显示顺序为名称偏好（全局，ADR 0006）> 本库来源名称 > 默认名称；跨库显示时为名称偏好 > 默认名称 > 按资料库固定顺序的第一个来源名称。迁入向导对上外部对应时：

- 原文与外部名称写法相同（规范化后，如 `blue eyes`、`Blue_Eyes`）：原文只是不分语言的标签别名，显示跟随默认名称。
- 原文是翻译表中某种语言的名称或别名（如简中别名“蓝眼睛”）：成为该语言的来源名称。
- 其他（包括没对上的）：按文字判断语言后成为来源名称。含假名为日文；含谚文为韩文；只有汉字时，界面语言是中文或日文就取界面语言，否则为简体中文；只有拉丁字母、数字与符号为英文；混排或其他为未注明语言，显示时排在其他语言之后。判错由画师在标签管理里改该名称的语言。
- 外部对应已属于库内另一个标签（例如模型先建了“蓝瞳”，或同库另一个 Eagle 标签 `blue eyes` 先对上了 `blue_eyes`）：Eagle 标签并入那个标签，原文只成为别名（是翻译表中某语言的叫法时为该语言的别名），仍可查找，显示跟随那个标签，例如“蓝眼睛”并入后显示“蓝瞳”。两边对应同一个外部名称，本来就是同一个标签，这不是 ADR 0003 否定的相近标签合并。

没对上的标签照常迁入；整理入口有两个：迁入向导的补对应一步，以及标签管理中的“没有外部对应”筛选。它们有来源名称，不算尚未翻译，标签上不另加标记。

已迁入过 Eagle 的资料库在升级时修正：来自 Eagle 的标签，当前名称与 `raw_item_json` 中某个 Eagle 原文完全相同的，按上面规则重判、重新匹配；不同的视为画师在 Kinshoko 里改过，保持名称来源待处理，交给 #182 的名称迁移，不直接成为名称偏好。

## Considered Options

- **原文当名称偏好**：重新迁入不再跟随 Eagle 改名，违背 ADR 0001 的分层；全局名称偏好又会被迁入顺序决定，违背 ADR 0006。
- **原文一律不注明语言**：不会判错，但英文原文在中文界面下与中文名称同等对待，界面语言切换时显示不出差别；维护者选择按文字判断，接受少量误判。
- **向导里让画师声明 Eagle 标签的语言**：Eagle 库通常中英日混用，一个声明管不住。
- **对上外部对应后两个标签并存**：同一外部对应只能属于一个标签，并存会让查找漏图。

## Consequences

- 只有汉字的日文词（如“制服”）会被记成中文，拉丁字母的罗马字（如 `hatsune miku`）会被记成英文；多数能按翻译对上，其余由画师改语言。
- 来源名称在跨库视图中只作兜底，不同资料库的 Eagle 叫法不互相覆盖。
- 普通导入图片内嵌的关键词（XMP/IPTC）不在此决定内，需要时另开导入来源。
