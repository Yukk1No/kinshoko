## 做了什么

### 后端（规则在 `kinshoko-core`）

- `Library::delete_folder`（`library/folders.rs`）：删除文件夹连同全部子文件夹，一个写事务完成。图片不删，只去掉这些文件夹的归属（`folder_member`）与画师的放入 / 移出决定（`folder_decision`）；没有其他文件夹的图因此回到未归类，回收站里的图留在回收站、还原后也在未归类。同级文件夹重新编号，不留空位。不认识的文件夹为 `UnknownFolder`，什么也不改。
- 来自 Eagle 的文件夹（`library/eagle.rs`）：删除时一并去掉 `eagle_folder` 对应。重导时：
  - 条目仍引用这个文件夹：在这个来源上次迁入的 Eagle 层级里查得到就略过这条归属，照常刷新（原来会以“Eagle 条目引用了不存在的文件夹”读失败）；层级里也没有的仍报这个错。
  - Eagle 层级变了（`sync_folders`）：上次迁入时就有、本库却没有对应的文件夹视为画师删掉的，不建回来；Eagle 之后在它下面新建的文件夹放到它原来的位置。
  - 不加迁移：被删的判断来自已保存的 Eagle 层级（`import_source.raw_library_json`）与上次迁入的层级。
- `Library::preview_empty_trash`（`library/permanent_delete.rs`）：清空回收站的预览，就是对回收站里浏览视角看得见的全部图做 `preview_permanent_delete`：同样的参考组核对与令牌；确认后交给原有的 `permanent_delete`，所以删除流程、崩溃恢复与 Eagle 重导记忆（`eagle_deleted_content`）都与彻底删除相同。安全模式开启时被封印的图不在其中，留在回收站。
- `DeviceLibraries::library_folder`（`device_libraries.rs`）：在资源管理器中打开图库用的位置——登记的位置，且那里仍是这个图库；移动盘拔出、搬家或换成了别的库时与登记检查同样的原因。只读，在登记表副本上检查。
- `src-tauri`（薄胶水，照现有命令写）：`library` 插件新增 `delete_folder`（经 `writable` 按需切换，同 `rename_folder`）、`preview_empty_trash`（同 `preview_permanent_delete`）；`desktop` 插件新增 `reveal_library`（`explorer.exe "<文件夹>"`，同 #105 的 `reveal_reference_image`）。`build.rs` 与命令列表同步登记。

### 前端

- `src/viewer/Viewer.tsx`：舞台即 `ContextMenu.Trigger`。菜单：钉住整图 `P` · 钉住局部 `F1` · 复制图片 · ─ · 适应窗口 `0` · 原始像素 `1` · 背景 ▸（深灰 / 中灰 / 浅灰 / 棋盘格，当前一档打勾）· 信息 `I`（勾选项）· ─ · 在资源管理器中显示 · ─ · 移到回收站（红字）。“钉住局部”已有选区时钉住它，否则进入框选。复制与显示直接用 #105 的 `copyReferenceImage` / `revealReferenceImage`，结果在钉图提示的位置说明（“已复制图片”“无法在资源管理器中显示：原因”）。“移到回收站”由调用方给出（`onTrash`）：`App` 按图片墙同一动作把卡片显示的那份来源移进回收站并关闭查看器；查看回收站里的图时没有这一项。菜单键 / Shift+F10 在舞台中心打开同一菜单；菜单（portal）里的按键不再冒泡触发查看器快捷键。
- `src/library/SidebarPane.tsx`：每个文件夹行一个右键菜单：新建子文件夹 · 重命名 `F2` · ─ · 移到顶层（顶层文件夹禁用）· ─ · 删除文件夹…（红字）。新建子文件夹的输入框出现在那个文件夹的子树下（图库标题菜单新建到所选文件夹时也一样）。文件夹行上按 `F2` 改名（新增），菜单键 / Shift+F10 打开菜单。删除文件夹走 `AlertDialog`：“删除文件夹「名称」？文件夹里的图片不会删除；不在其他文件夹里的图片回到未归类。”有子文件夹时加一句“其中的 N 个子文件夹也会一并删除，里面的图片同样保留。”正在看的文件夹（或其子文件夹）被删后回到该图库的全部。
- `src/library/WorkspacePane.tsx`：`LibraryMenuItems` 补齐：新建文件夹 · 在资源管理器中打开 · 重新连接（未连接时）· ─ · 从列表移除；`⋯` 与图库标题行的右键菜单用同一份。未连接时名称按钮禁用且不接收指针（`main-window.css`），右键与路径 / 原因的悬停提示落在整行上。“从列表移除”与管理图库对话框的“移除”相同（取消登记，文件不删），移除的是窗口打开时的图库时 `App` 随之按“没有当前图库”处理。回收站行的右键菜单：清空回收站…（红字）；“全部图片”下按图库各一项“清空「库名」的回收站…”；回收站为空时禁用。
- `src/library/SelectionPanel.tsx`：`PermanentDeleteConfirm` 加 `emptyTrash` 用法：标题“清空回收站”、文案“永久删除「库名」回收站里的 N 张图？原图与整理结果都会删除，无法恢复。”、受影响的参考组列表与预览过期后重新列出都沿用原样；预览为 0 张时不能确认。
- `src/ui/menuKey.ts`：菜单键判断与在元素中心派发 `contextmenu` 从 `Wall.tsx` 移出，图片墙、查看器与侧栏共用。
- `src/ipc.ts`：`deleteFolder`、`previewEmptyTrash`、`revealLibrary`。
- `design/ui-system/README.md` 组件对照随之更新。

### 决定

- 删除文件夹时子文件夹一并删除（不上移到父级），确认框写明；图片无论在哪一层都不删。
- “从列表移除”不另弹确认，与管理图库对话框一致（文件不删，可再“打开图库…”加回）。
- 清空回收站只删看得见的：安全模式下被封印的图不在预览里，也不被删除。
