## 实现

- **按需切换**（[`device_libraries.rs`](../../crates/kinshoko-core/src/device_libraries.rs)）：`organize(library_id)` 把唯一的可写句柄切到目标图库，不改动“上次打开”。目标图库或当前持有者有导入处于收尾发布阶段时返回 `Waiting`：等待在该导入结束时唤醒，另有超时，调用方重新请求，所以请求不丢、不重复执行。仍在处理图片的导入不阻止切换（导入在原图库继续，回执留在原图库）。未登记或不可用的图库被拒绝，持有者不变。
- **Tauri 胶水**（[`src-tauri/src/library.rs`](../../src-tauri/src/library.rs)）：新增 `writable()`，取句柄的方式与 `switch_library` 相同；需要等待时发一次 `organize-waiting`（轻提示），等完再执行；切换后发 `writable-library`。`edit`、`create_folder`、`rename_folder`、`move_folder`、`edit_tags`、`preview_permanent_delete`、`permanent_delete` 都改为经它取得资料库，移除不再使用的 `library::current()`。
- **跨图库批量**（[`library_batch.rs`](../../crates/kinshoko-core/src/library_batch.rs)）：`group_by_library` 按第一次出现的先后分组、组内去重；`each_library` 逐组执行，一组失败不影响其他组，结果按图库返回。新命令 `preview_permanent_delete_batch`、`permanent_delete_batch`（已在 `build.rs` 登记）每组都经 `writable()`，同样等导入收尾。
- **前端**（为 #113 的界面改版留余地，只做最小改动）：
  - 侧栏与工作区：任一已连接图库的目录都能整理（去掉只读门槛）；从图片墙拖出时带上每张图在各图库里的 id（`DRAG_IMAGE_SOURCES`），放下时用目标图库里的 id。
  - 轻提示：“导入收尾后再整理”，说明“「库名」的导入完成后自动执行”。
  - 任一图库的刷新事件（列表、词表、图片）都会重新加载视图；另一个图库的安全模式与导入事件仍被忽略，不串台。
  - 打标指示跟随后端的可写图库，忽略旧图库迟到的状态。
  - 右键菜单（[`useWallActions.tsx`](../../src/wall/useWallActions.tsx)、[`PermanentDeleteBatch.tsx`](../../src/library/PermanentDeleteBatch.tsx)）：多张彻底删除可以跨图库，不再提示“逐张彻底删除”。断连的图库在对话框里说明这次删不了，确认后其余图库照常删除，没删完的按图库报告；预览过期的图库重新列出后再确认。同一个参考组涉及多个图库时合成一行。分级、放入、回收站与加入参考组逐张执行，一个图库失败时其他图库照常完成，最后按图库报告。

## 评审修正（分支 `impl/review-fixes`）

2026-10-16，集成分支 `5fa90ef` 的代码评审之后。

- **读不再要求可写库**：浏览、详情、目录、词表、标签、候选、条件解析、分级等读命令原来经 `require` 只认“活动资料库”，整理过另一个库（可写句柄切走）后，窗口打开的库读详情、标签都报“资料库已切换”。现在经 `DeviceLibraries::resolve` 按 id 取：可写库或导入仍持有的库沿用其句柄，其他库只读打开、按设置的安全模式读，读不切换句柄。标签分组与个人近似对应的写命令改经 `writable()`。
- **事件按库转发**：转发线程原来只转发活动资料库的事件，A 库导入中整理 B 库后 A 的进度、结束与列表变化都丢了。现在每个句柄的事件都转发（都带资料库身份），界面照旧只采纳它显示的库的安全模式与导入事件。安全模式开关与设置恢复改为设给所有开着的可写句柄（`DeviceLibraries::set_safe_mode`），切走的库不留旧视角。
- **等待有上限**：等导入收尾的循环移到 core（`wait_for_writer`），总共等 120 秒仍在收尾时报错“「库名」的导入一直没有收尾，这次整理没有执行，请稍后再试”，不再让整理请求永远挂着。
- **来源整理同走 `writable()`**：图片墙右键与查看器里的整理（`workspace_edit_source`、`workspace_edit_source_tags`、`workspace_permanent_source_delete`）原来经 `DeviceLibraries::write` 另开句柄，绕过按需切换与导入收尾等待；现在先 `writable()`，再用 `Workspace::write_source_with` 在这个句柄上执行。
- **“在 Kinshoko 中打开”的卡片**：原来卡片 id 用的是图库里的图片 id，查看器里“移到回收站”等把它当字节身份核对来源，总是“来源记录已变化”。新命令 `workspace_card`（core `Workspace::card`）与图片墙同样构成卡片。
- **删除正在接收导入的文件夹**：拒绝，提示“这个文件夹（或它的子文件夹）正在接收导入，导入结束后再删除”（原来剩下的导入项会失败）。
- **跨图库彻底删除部分完成**：有图库已删完、其他图库预览过期正在重新列出时取消，也刷新并取消选择。
- **“从此文件夹移出”**：默认的含子文件夹范围里，图直接在这个文件夹时也显示（菜单打开时读一次这张图的文件夹）。

检查：`tests/writer_switch.rs` 新增 3 项（读不要求可写库、安全模式设给所有可写句柄、等待上限），`tests/source_actions.rs` 新增 2 项（`write_source_with`、`Workspace::card`），`tests/organize.rs` 新增 1 项（导入中删除文件夹）；vitest 新增 `useWallActions` 2 项、`WallMenu` 1 项、`openInKinshoko` 改写 1 项，均先红后绿。`cargo test -p kinshoko-core --no-fail-fast` 只有已知的 `tagger_process` 4 项失败；`cargo fmt --all --check`、`cargo clippy -p kinshoko-core --all-targets -- -D warnings`、`npm run typecheck` 通过；整套 vitest（`--maxWorkers=2 --testTimeout=30000`）76 个文件 615 项全部通过。`src-tauri` 仍未在容器里编译。

## 设计带来的后果

- **打标跟着可写图库走**：在两个图库之间来回整理时，每次切换都会重启打标子进程、重新加载模型。
- **来回切换会重开被切走的库**：被切走的库（没有导入持有时）随即关闭，切回来时重新打开，要做一次恢复对账、启动占位图补齐线程（缺占位图时才解码，否则每张图只查一次文件是否存在）并同步统一标签目录。评审时考虑过把切走的库留着不关（切回不重开），没有采用：它会一直占着该库的数据库文件，移动盘上的库在 Windows 上无法安全弹出、目录无法改名。图库很大、来回切换频繁时这部分开销需要在开发机上实测（见下节）。
- **详情面板的多选仍只限一个图库**：`SelectionPanel` 的多选操作只作用于窗口打开时的图库，跨图库多选留给 #113 与界面改版；右键菜单已经可以跨图库。
