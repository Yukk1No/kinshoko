## 实现

- **按需切换**（[`device_libraries.rs`](../../crates/kinshoko-core/src/device_libraries.rs)）：`organize(library_id)` 把唯一的可写句柄切到目标图库，不改动“上次打开”。目标图库或当前持有者有导入处于收尾发布阶段时返回 `Waiting`：等待在该导入结束时唤醒，另有超时，调用方重新请求，所以请求不丢、不重复执行。仍在处理图片的导入不阻止切换（导入在原图库继续，回执留在原图库）。未登记或不可用的图库被拒绝，持有者不变。
- **Tauri 胶水**（[`src-tauri/src/library.rs`](../../src-tauri/src/library.rs)）：新增 `writable()`，取句柄的方式与 `switch_library` 相同；需要等待时发一次 `organize-waiting`（轻提示），等完再执行；切换后发 `writable-library`。`edit`、`create_folder`、`rename_folder`、`move_folder`、`edit_tags`、`preview_permanent_delete`、`permanent_delete` 都改为经它取得资料库，移除不再使用的 `library::current()`。
- **跨图库批量**（[`library_batch.rs`](../../crates/kinshoko-core/src/library_batch.rs)）：`group_by_library` 按第一次出现的先后分组、组内去重；`each_library` 逐组执行，一组失败不影响其他组，结果按图库返回。新命令 `preview_permanent_delete_batch`、`permanent_delete_batch`（已在 `build.rs` 登记）每组都经 `writable()`，同样等导入收尾。
- **前端**（为 #113 的界面改版留余地，只做最小改动）：
  - 侧栏与工作区：任一已连接图库的目录都能整理（去掉只读门槛）；从图片墙拖出时带上每张图在各图库里的 id（`DRAG_IMAGE_SOURCES`），放下时用目标图库里的 id。
  - 轻提示：“导入收尾后再整理”，说明“「库名」的导入完成后自动执行”。
  - 任一图库的刷新事件（列表、词表、图片）都会重新加载视图；另一个图库的安全模式与导入事件仍被忽略，不串台。
  - 打标指示跟随后端的可写图库，忽略旧图库迟到的状态。
  - 右键菜单（[`useWallActions.tsx`](../../src/wall/useWallActions.tsx)、[`PermanentDeleteBatch.tsx`](../../src/library/PermanentDeleteBatch.tsx)）：多张彻底删除可以跨图库，不再提示“逐张彻底删除”。断连的图库在对话框里说明这次删不了，确认后其余图库照常删除，没删完的按图库报告；预览过期的图库重新列出后再确认。同一个参考组涉及多个图库时合成一行。分级、放入、回收站与加入参考组逐张执行，一个图库失败时其他图库照常完成，最后按图库报告。

## 设计带来的后果

- **打标跟着可写图库走**：在两个图库之间来回整理时，每次切换都会重启打标子进程、重新加载模型。
- **详情面板的多选仍只限一个图库**：`SelectionPanel` 的多选操作只作用于窗口打开时的图库，跨图库多选留给 #113 与界面改版；右键菜单已经可以跨图库。
