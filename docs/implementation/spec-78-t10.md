# #78 T10：明确保存目标与长任务归属

关联：[独立规格 #78](https://github.com/Yukk1No/kinshoko/issues/78)；[工单 #89](https://github.com/Yukk1No/kinshoko/issues/89)。这是本次增量实现记录。没有改写 #42、PR #71 或此前验收记录。

## 实现与边界

全局导入入口要求明确选择资料库和文件夹。选择“未归类”也是明确的选择。具体目录入口可以预填该目录。浏览范围、查询条件、当前查看位置及当前资料库不再决定全局保存目标。认可原型的紧凑导入入口继续使用正式控件；普通导入与 Eagle 导入在开始前显示最终位置并要求确认。

普通导入、Eagle 导入、参考组包、截图收藏、截图参考组和明确来源的跨库复制都绑定最终保存目标。参考组中的截图可以分别选择资料库和文件夹。复制使用真实来源的内容快照、原图和来源记录；不会覆盖目标库中同一文件已有的独立人工备注和标签，不增加公共资料池。

核心 `SaveDestination` 包含资料库 ID 和可空的文件夹 ID；空文件夹表示明确保存到未归类。固定目标的 Library 包装共享实际写句柄。目标资料库身份和文件夹在执行及内容事务提交时验证。失效后停止该项并给出实际原因；已完成项保留，不静默改放其他库或未归类。

`DeviceLibraries::write` 在短锁内取得缓存的实际 `Arc<Library>`。长任务持有该句柄；切换 current、新建资料库、改变下一次目标及重新打开原库都不取消正在运行的其他库任务，不重新打开并 reconcile 该任务正在写入的 pending。注销库只撤销该库的保存权限并取消该库任务。取消及关闭回执同时验证任务 ID 与实际拥有库。

公开 `ImportTaskSnapshot` 给出任务 ID、固定目标、目标名称、真实进度、实际分项报告、定义发布收尾状态及警告。`finishing` 表示仍需完成定义发布；内容完成必须以真实 `report` 存在为准，不能只看该标记。界面切换浏览或选择下一次目标后，仍显示原任务位置并操作原任务。迟到进度和收尾回执按任务 ID 归并。重试默认恢复原目标；用户在确认前明确选择其他目标时，实际提交与可见目标一致。

普通导入、截图收藏及跨库复制完成后，经固定目标的句柄发布 T11 的可携带标签定义。发布失败保留已完成内容并显示可重试的警告。Eagle 后续绑定选择也发布到其真实拥有库。包导入复用 T11 的完成分支，不重复发布。跨库复制通过未筛选的目录快照复用 `CatalogInspection::apply_content_definitions`，不将名称偏好写入内容。取得来源和引用快照后才锁目录，保持应用的锁顺序。

正式钉图菜单“收藏到…”打开主窗口中的目标确认。请求在订阅前到达时仍可经 `take_collection_request` 取回。新增命令同时登记 handler、build.rs 及既有默认 ACL。截图原图流程没有另建重编码路径。
