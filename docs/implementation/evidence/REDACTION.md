# 证据脱敏记录

本仓库公开。按开源隐私惯例，已提交的证据不得包含个人数据；含个人数据的原始证据只在维护者本机保留，仓库内仅以 SHA256 引用。本文件记录一次前向脱敏提交（没有改写历史，也没有强推），并给出每个被改动或移除文件的原始与新 SHA256，使此前各文档与 JSON 中的 SHA 引用仍可追溯。文档与 JSON 内部原有的 SHA 引用保持原样，未改写。

基线提交：`c826269`。

## 不允许出现在已提交文件中的内容

- 路径中的操作系统用户名（`C:\Users\<user>`、JSON 转义的 `C:\\Users\\<user>`、`C:/Users/<user>`、`/c/Users/<user>`，任意大小写）
- 主机名、Windows SID
- GitHub noreply 以外的邮箱地址
- 令牌或密钥
- 整个桌面的截图、显示测试夹具以外内容的冻屏图、暴露本机文件夹的保存对话框控件树
- 显示本机用户目录、真实用户文件或个人数据的截图

## 方法

1. **清点**：对全部受跟踪文件做大小写不敏感的文本扫描（UTF-8、带 BOM 的 UTF-8 与 UTF-16 均解码后扫描），并检查二进制文件与 gzip 压缩内容。扫描结果中只有用户主目录前缀一类命中；未发现主机名、SID、真实邮箱或令牌（`icon@2x.png` 一类文件名不是邮箱）。
2. **文本**：把用户主目录前缀替换为 `%USERPROFILE%`，路径其余部分保持不变；分隔符风格（`\`、`\\`、`/`）原样保留。除此之外不改任何字节，编码、BOM 与换行保持不变；每个改动过的 JSON 都重新解析通过。共 728 个文本文件；另有 4 个 Markdown 只改了下述图片链接说明，表中合计 732 个文本文件。
3. **gzip**：两个 T17 `result.json.gz` 解压后按同一规则替换，再以相同头信息（mtime 0、无文件名）重新压缩；解压后的 JSON 仍可解析。共 2 个。
4. **图片**：逐张目视检查仓库内全部图片。48 张应用窗口截图在错误横幅、已登记资料库列表、导入/复制目标、备份位置或设置备份字段中显示完整本机路径（含用户名），已移出仓库并仅在本机保留；指向它们的 Markdown 链接改为一段说明，附原 SHA256。其余证据截图只显示应用窗口与测试夹具（路径已被应用省略为 `…\libraries\…`，或被模态框遮住），设计稿、标志与图标图片不含个人数据，均保留。
5. **例外**：`docs/implementation/evidence/spec78-t20/` 在另一分支上单独脱敏，本次未改动。`e2e/` 下若干脚本把 `tauri-driver.exe` 的默认路径写成本机绝对路径，这是源码而非证据，本次未改动，另行处理。
