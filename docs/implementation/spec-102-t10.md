## 实现

- **步进与格数**（[`src/wall/zoom.ts`](../../src/wall/zoom.ts)）：`zoomDensity` 每格 ×1.1（往下 ÷1.1）取整到 10，停在 140–420，往上滚为正。`createNotchCounter` 把滚轮事件折算成格数：鼠标的一格不论系统缩放报 100、125 还是 150 像素都只算一格；精确式触控板捏合（Ctrl+小增量）累积到半格（50 像素）才算一格，换方向重新累积。#108 的场景脚本 `zoomSteps` 改用同一个 `zoomDensity`。
- **图片墙**（[`Wall`](../../src/wall/Wall.tsx)）：在滚动容器上手动加 `wheel` 监听（`passive: false`；React 的 `onWheel` 是被动监听，不能阻止页面缩放），只处理带 Ctrl 的滚轮并 `preventDefault`。每格：
  - 本地预览：先 `measureBeforeReflow`（与滑条预览相同的重排动画），再同步设预览密度；通过新属性 `onDensityPreview` 告诉父界面。
  - 锚点：用纯函数 [`cardAt`](../../src/wall/layout.ts)（落在缝隙或边距里时取离得最近的一张）找光标下的图；布局效果把它的中心放回光标下的纵坐标，随后以新布局里视口顶部的图重新取锚并保存，所以提交时布局不变、位置不动。同一次连续缩放里光标没动就一直锚同一张图。列数变化时横向位置由瀑布流决定，无法保持（图片墙没有横向滚动），只保证纵向。
  - 提交：最后一格后 220 ms 调 `onDensityCommit`；缩回原值时只撤掉预览（`onDensityPreview(null)`），不提交。提交后密度变化，沿用已有逻辑按新尺寸（`thumbnailPx`）重新浏览、取缩略图。停手前图片墙被重建（换范围）时也落下这个值。
  - 滑条与键盘改密度仍走 `previewDensity`，不设光标锚，以视口顶部的图为锚（未改）。
- **滑条联动**（[`DensitySlider`](../../src/wall/DensitySlider.tsx)、[`DensityIsland`](../../src/wall/DensityIsland.tsx)、`App.tsx`）：新属性 `preview`，滑条显示缩放中的预览值；`App` 持有 `zoomPreview`，提交时与 `density` 一起更新。滑条自身的提交逻辑未改，缩放不经滑条重复提交。
- **页面缩放与其他窗口**：`tauri.conf.json` 没有开启 `zoomHotkeysEnabled`（默认关），图片墙另外对 Ctrl+滚轮 `preventDefault`。查看器（`Viewer.tsx` 的舞台监听）与钉图窗口（`PinView.tsx`）的 Ctrl+滚轮代码未改；查看器盖在图片墙之上，事件不经过图片墙。
