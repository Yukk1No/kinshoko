## 做了什么

### 后端（规则在 `kinshoko-core`）

- `crates/kinshoko-core/src/library/clipboard.rs`：
  - `Library::clipboard_pixels`：复制图片的像素。经浏览视角（没有这张图、安全模式下被封印都是 `UnknownImage`）；取显示管线的原尺寸源（静态 SDR 原图，或特殊声明 / 动图 / HDR 的原尺寸 SDR 派生图），用钉图“复制”已有的 `clipboard_rgba` 转成原尺寸、按方向转正、不带配置文件的 sRGB RGBA8。剪贴板图片不能携带 ICC，所以颜色要先转换。
  - `Library::reveal_original`：原文件位置；文件已不在时 `Error::OriginalMissing(路径)`（“原文件不在了，可能被移走或删除：…”），不静默失败。复制时原文件不在也报这个错。
  - `stage_clipboard_image(dir, image)`：把剪贴板图片写成 `dir` 下一个新的无损 PNG（`剪贴板图片-<毫秒>.png`，同名时加序号），交给普通导入；空图为 `Error::ClipboardImage`，失败不留文件；一天前暂存的文件顺手清掉。
- `src-tauri/src/desktop/image_actions.rs`（`desktop` 内联插件的四条命令，`build.rs` 同步登记）：
  - `copy_reference_image`：经 `library::visible_source` 取图、解码、准备剪贴板格式（沿用 `clipboard::PreparedImage`：PNG + CF_DIBV5），在可见性提交里重新核对可见后才写剪贴板。
  - `reveal_reference_image`：`explorer.exe /select,"<原文件>"`；文件不在时返回原因，不打开窗口。
  - `clipboard_has_image`：Windows 上只看格式（CF_DIB / CF_DIBV5 / CF_BITMAP / PNG），不读出图片。
  - `stage_clipboard_import`：arboard 读剪贴板图片（与 F3 钉剪贴板相同），写到应用数据目录的 `clipboard-import/`，返回路径。

### 前端

- `src/wall/WallMenu.tsx`：单张菜单加入“复制图片 `Ctrl C`”（框选局部钉住之后）与“在资源管理器中显示”（自成一组，在移到回收站之上）；空白处加入“从剪贴板导入 `Ctrl V`”，菜单打开时读一次剪贴板，没有图片时禁用（读不出时不禁用，真去导入时再报告原因）。多张仍是禁用的“复制”。
- `src/wall/useWallActions.tsx`：`copy`（成功轻提示“已复制图片”，失败提示“无法复制图片：原因”）、`reveal`（失败提示“无法在资源管理器中显示：原因”）、`importClipboard`、`clipboardHasImage`。都按卡片显示的那份来源（与钉住、整理相同）。
- `src/wall/Wall.tsx`：`Ctrl+C` 按右键的同一选择规则（焦点卡片未选中时选择改为它）交给调用方，多张时提示“一次只能复制一张”；`Ctrl+V` 在主窗口里只要焦点不在输入框、没有模态与查看器、工作区没隐藏就从剪贴板导入。
- `src/library/ImportMenu.tsx` / `ImportBar.tsx`：`ImportControl.clipboard` 先暂存剪贴板图片，再走与“图片文件…”相同的入口（`ImportActions.paths`）：导入对话框、保存位置明确选择（在文件夹里浏览时预填这个文件夹）、进度与结果回执都不变。正在导入时以“正在导入，结束后再从剪贴板导入”拒绝。
- `src/ipc.ts`：`copyReferenceImage`、`revealReferenceImage`、`clipboardHasImage`、`stageClipboardImport`。

### 查看器菜单

查看器还没有右键菜单（由 #114 接入）。本单的 `copyReferenceImage` / `revealReferenceImage` 已可直接给查看器菜单的“复制图片”“在资源管理器中显示”使用；查看器里本单未加入口。

| 在资源管理器中显示 | 无（#114 的查看器菜单将再提供一处） |
| 从剪贴板导入 | 主窗口 `Ctrl+V`（新增）；F3 钉剪贴板仍是钉到桌面，不进库 |
