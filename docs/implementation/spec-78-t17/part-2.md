## 历史锁不跨越编码与完整导入

独立静态审计发现 F3 持历史锁编码 PNG，手动收藏与参考组收藏持历史锁等待完整导入。
F1 最终 gate 和关闭截图 pin 的 gate 都会再等该历史锁，因而可间接把昂贵准备拖入撤销等待。
这是静态可达链，尚无该链的独立原生时序或硬耗时上限结论。

`CaptureDraft::commit_with_history` 仅在普通截图分支调用历史持久化闭包；原图复制与钉图完全不申请历史锁。
F3 使用公开 opaque `PreparedCapture`：PNG 编码在锁外完成，再持锁写已准备的字节。
两处正式收藏入口都使用 `prepare_collect` → 锁外真实 `CaptureCollection::import` → `finish_collect` / `finish_collect_pin`。
收藏请求通过独立 Arc 保留原 PNG，不增加真实 pin 计数。删除/超限可以立即移除可见历史条目，不在完成后恢复它。
只有条目已被回收且最后一个收藏请求结束时，RAII 才删除文件；仍有真实 pin 时维持既有保留规则。
成功、导入失败和未导入放弃都释放请求。有效历史正常 drop/退出不标记删除，持久 PNG 保留。
同目录仍由一个运行中的历史实例管理；重新打开目录前结束旧实例的收藏请求。进程中断留下的孤立文件仍由下次启动清理。

公开接口编译 RED 与真库 GREEN 原件见 [history-lock](../evidence/spec78-t17/history-lock/index.json)。
最终窄测试 26/26：原图分支不调用历史闭包；真实完整导入在测试线程仍持历史锁时完成；多个收藏、删除/超限、失败/放弃、真实 pin 仍开与最后关闭均符合文件生命周期。
收藏后的原图尺寸、crop、placement、透明度、锁定和 group member 保持原值。有效历史退出后 PNG 仍可读回。
编译 RED 只证明新增公共接缝尚不存在，不冒称旧静态链的运行时复现。
普通历史提交仍需短暂持锁写文件/索引，OS 和文件系统可能延迟；没有新增硬实时上限承诺。最终授权仍重验真实 mode、membership 与 veils。
