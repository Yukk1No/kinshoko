## 实现与边界

正式设置入口称为“资料库备份”。说明中明确原图、逐图整理、目录、关联参考组和标签定义属于内容备份；名称偏好、程序标签分组和个人近似规则属于独立的程序设置备份。T13 负责后者。本单没有增加设置包。

`BackupTarget::run_with_catalog` 复用既有范围计算、SQLite Online Backup、原图租约、增量原图存储、计划和保留策略。应用适配器先取得完整 `CatalogInspection`。内容快照只在私有 SQLite 副本上注入程序当前的纯定义。它与 T11 的包导出、定义发布共用 `CatalogInspection::content_bindings`。来源 provider 不因此发生隐式写入。

快照保存稳定标签 ID、本地标签映射、命名空间、默认名称、别名和外部对应。它不保存显示名称偏好。程序中已经纠正或拆分身份、删除别名后，即使来源只读或显式定义发布失败，内容备份仍携带当前定义。封印依赖仍由完整原始目录处理，不经过界面安全投影。

快照副本删除旧资料库中的标签分组和个人近似迁移行。恢复旧版本整库快照时也只在恢复副本删除这些行。这样，新库 ID 不会让旧迁移设置重新登记或复活。旧来源数据库保持原状。往返检查明确只比较内容表，返回实际检查的表数。

`BackupTarget::restore_with_catalog` 在创建恢复目录前核对目标程序已有稳定身份及命名空间。冲突先拒绝，不修改当前内容或设置。恢复继续生成独立资料库与参考组 ID，记录恢复来源，将组成员指向本批次恢复的库。原图不重新编码。逐图人工标签、拒绝标签、备注、内容分级、目录层级以及参考组裁剪、翻转、旋转、缩放和布局保留。

已有环境恢复后，当前程序的名称偏好、别名删除记忆、全局分组成员和个人近似决策及来源确认记录保持。空白环境只从内容定义解释标签，不带入源程序偏好、全局分组或个人规则。

## 中断恢复契约

一次恢复先在目标目录的独立 `.kinshoko-restore-<id>.incomplete` 中准备所有库和组。发布第一个库前，程序在 `reference-groups/restore-transactions/` 持久保存本批次的完整新身份、目标位置和恢复来源记录。库和组分别发布。这里没有跨文件系统或跨存储的原子事务。

普通写入错误立即回退本批次。进程在库或组发布阶段中断后，下次程序启动或恢复重试会读取记录，先核对全部目标的身份、位置和恢复来源，再撤回本批次新库和新组。既有库、既有组和当前设置不属于该记录。目标被用户替换、移动或身份不符时，程序保留现场并报告回退未完成，不删除不明内容。回退成功后可重新执行完整恢复。

核心恢复入口使用进程级 `RESTORE_GATE`，与同一程序的恢复和启动回退互斥。Tauri 启动入口在备份管理器建立时执行回退，主窗口打开前完成。恢复本身不拿程序目录写锁；所需定义已事先取得不可变快照。

## 红灯与公开检查

真实公开检查使用 `Library`、`TagCatalog`、`BackupTarget`、`ReferenceGroups`、SQLite 和原文件。原始失败记录及后续通过记录逐字节保存在 [T12 证据目录](evidence/spec78-t12/README.md)。完整原件仍保留在本工作树 ignored `work/`。

- `t12-red-freshness` → `t12-green-freshness`：程序纠正与别名删除后，只读来源发布失败；内容备份仍在空白应用还原当前身份和纯定义。
- `t12-red-settings-ownership` → `t12-green-settings-ownership`：内容恢复不迁入旧全局分组和个人近似。
- `t12-red-legacy-snapshot-settings` → 完整备份回归：旧整库快照恢复也不能复活程序设置，来源旧行仍在。
- `t12-red-batch-rollback` → `t12-green-batch-rollback`：多库后一库原图损坏，不留下可用的前一库。
- `t12-red-target-identity` → `t12-green-target-preflight`：目标同一稳定 ID 的命名空间冲突，在发布内容前拒绝。
- `t12-red-ui` → `t12-green-ui`：正式入口名称和内容、设置边界。

`backup_content_definitions` 的 8 个父测试通过。两个 ignored 子进程入口由父测试实际调用。故障覆盖定义注入事务的 SQLITE_FULL 和退出码 99，以及首库发布后、首组发布后的 SQLITE_FULL 和退出码 99。中断后重开、整批回退、旧内容与设置保持、完整重试都检查实际公开结果。没有把 ignored 入口当作未运行。
