# Eagle 首次迁入（#57）

入口：打开一个 Kinshoko 资料库，选择「从 Eagle 迁入…」，选中自动找到的来源库；也可手动选择、导入文件夹或拖放 Eagle 资料库文件夹。只读取 Eagle 原库，原图走普通导入共用的暂存 → pending → 发布 → 提交管线。

## 自动检查

`cargo test -p kinshoko-core --test eagle_import --test eagle_crash` 使用临时目录中的真 SQLite 与真文件，通过核心 crate 的公开接口检查。

- 仿真库生成器移植自 `prototype/storage-roundtrip/make_eagle_fixture.py`，分别生成 Eagle 1.8.2、4.0.0 的主库（150 项）与第二个库（20 项）。包含嵌套和空文件夹、一图多文件夹、链接、备注、区域评论、回收站、同库重复、无文件夹、主色及未知字段。
- 条目和库级 `metadata.json` 原样保存，包括空白与未知字段；重开后来源快照相同。区域评论完整保存并标记 `eagle-raw-unverified`，首版不显示坐标。
- 导入前后原图 SHA-256 一致；来源原图与元数据未改变。只枚举 `images/` 下的 `.info` 条目，不迁入 Eagle 缩略图，不以 `mtime.json` 为准。
- 同库同字节原图合并为一条参考图，两个条目的原始 JSON、标签、备注、链接和文件夹关系均保留。两个 Kinshoko 资料库独立保存共有原图及人工整理。
- Eagle 回收站条目首次迁入时进入可恢复删除，使用 `deletedTime`；缺失时使用导入时间。重复提交同一条目不会再次删除已恢复的图，也不覆盖本库人工备注与标签决定。
- 收集时间按 `btime` → `modificationTime` → 导入时间取值。字段含义按名称推断，未经 Eagle 界面核实，按 #42 已接受的映射处理。
- 不按 `applicationVersion` 拒绝导入；缺失必需字段、无效 JSON、大小不符和越界文件名逐项报告失败。重试失败项仍作为 Eagle 条目处理，保留成功项、补齐来源事实且不重复创建记录。
- 来源链接接入 #54 的文字检索，可以按链接中的文字找回迁入的参考图。
- 找库按本地 API → `%APPDATA%/Eagle/Settings` → 磁盘回退。API 超时 2 秒，回退扫描最多 40 秒、5 层，跳过系统目录、AppData、node_modules、符号链接等；候选按实际条目数排序。
- 两个版本分别在暂存、pending、原图发布、事务提交前强制退出子进程。重开撤回未提交项，不留下半份来源事实；重试补齐，已提交项不重复。

在画师电脑上用 Eagle 实际写出的资料库迁入，核对整图、文件夹层级、多文件夹关系、标签、链接、备注及回收站，并记录版本与导入耗时。本地仿真库不能替代真实 Eagle 的格式兼容复核。
