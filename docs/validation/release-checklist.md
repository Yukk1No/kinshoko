# 发布前检查清单

首版发布前人工执行、逐项记录通过／不通过的检查。自动测试覆盖不到、需要真机、真笔或画师电脑的项目放在这里；门槛的来源见 [验收约定](acceptance.md)。每次发布复制本清单，填上日期、版本、机器与结果。

## 开发机：模拟键鼠检查

在开发机上用发布构建（`target/release/kinshoko.exe`）运行，运行期间不要碰键鼠，也不能有别的 Kinshoko 或占用 F1/F3/F4 的程序（例如 Snipaste）在运行。

| 检查 | 命令 | 100% | 125% | 150% |
|---|---|---|---|---|
| 截图钉图逐像素一致（#62） | `python scripts/probe/capture_pin.py target/release/kinshoko.exe` | | | |
| 贴边隐藏、交还焦点、碰细边滑出（不改原生窗口、收起时点击穿过）、翻转旋转、重开恢复（#63、#64） | `python scripts/probe/edge_restore.py target/release/kinshoko.exe` | | | |

非整数缩放（125%、150%）下钉图不被重新采样：两个脚本的像素比较都要通过。滑出后的钉图停在伸出屏幕的窗口里、带整数物理像素的平移（#64），`edge_restore.py` 的“指针碰细边时滑出”逐像素比较覆盖这一点。

## 开发机：钉图右键菜单与动画（#64）

发布构建，100%、125%、150% 各做一遍；鼠标与数位笔（Windows Ink、WinTab 两种模式）各做一遍：

- [ ] 鼠标右键弹出菜单；笔的侧键弹出菜单；笔尖按住钉图不动约半秒弹出菜单。同一次按下只弹一次。
- [ ] 菜单里水平翻转、垂直翻转、顺时针／逆时针旋转都生效，旋转时中心不动。
- [ ] 透明度子菜单 10%～100% 生效，当前值打勾；Ctrl+滚轮每格 10%。
- [ ] 勾选“锁定位置与大小”后，鼠标、笔都拖不动钉图，滚轮和右下角都缩放不了，“原始大小”变灰；取消勾选后恢复。
- [ ] 透明度与锁定在结束进程再启动后恢复。
- [ ] 滚轮连续缩放、拖右下角缩放时钉图平滑变化，不一抖一抖；缩放停下后钉图清晰（逐像素重画）。
- [ ] 贴边收起、碰细边滑出、离开收回、再按 F4 回原位都是平滑滑动。
- [ ] 动画开始或结束改原生窗口的那一下，钉图没有闪一下或跳一帧（收到左边、上边与从左边、上边回原位时最容易看到；滚轮以光标为中心缩放时也注意看）。出现时记下缩放比例与机器。
- [ ] 收起后细边旁边原本被钉图挡住的地方可以正常点到下面的程序（窗口点击穿过）；滑出后钉图能拖动。
- [ ] 多显示器：收到与相邻显示器相接的边时，收起的部分不出现在相邻显示器上挡住点击（#63 起已知的边界情况，记录现象）。

## 开发机：数位笔（#63）

数位板驱动分别切到 **Windows Ink** 与 **WinTab** 模式，各做一遍：

- [ ] 用笔按住钉图拖动，钉图跟手移动。
- [ ] 用笔按住钉图右下角拖动，钉图缩放、左上角不动。
- [ ] 用笔点一下钉图后按 F4，钉图收到屏幕边，笔随即能在绘画软件里画，不需要先点一下绘画软件。
- [ ] 笔悬停碰到细边时钉图滑出，离开后收回。
- [ ] 截图框选区域里用笔拖动框选，不触发系统手势。

## 发布与自动更新（#70）

### 一次性准备（只有仓库所有者能做）

更新签名私钥只放在 GitHub 仓库的 Actions secret 里，**不进仓库、不发给别人**；公钥写进 `src-tauri/tauri.conf.json`。没有这两样时，发布工作流照常构建安装包，但跳过更新包签名与 `latest.json`（日志里有警告），已安装的 Kinshoko 也不会检查更新（设置里显示“此构建未启用自动更新”）。

1. 在自己的电脑上生成密钥对（设一个密码；私钥文件放在仓库目录之外，并另外备份——丢了私钥或密码，已安装的用户就再也收不到更新）：
   ```
   npx tauri signer generate -w %USERPROFILE%\.tauri\kinshoko-updater.key
   ```
2. 仓库 **Settings → Secrets and variables → Actions → New repository secret**，建两个 secret：
   - `TAURI_SIGNING_PRIVATE_KEY`：`kinshoko-updater.key` 文件的全部内容；
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：第 1 步设的密码。
3. 把 `kinshoko-updater.key.pub` 的内容（一行 base64）填进 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`，提交。公钥可以公开。
4. **更新地址必须能匿名访问。** `plugins.updater.endpoints` 指向 `https://github.com/Yukk1No/kinshoko/releases/latest/download/latest.json`；仓库目前是私有的，画师的 Kinshoko 访问它会得到 404，自动更新不会工作。二选一：把仓库改为公开；或另建一个公开的发布仓库，把 endpoints 改成那个仓库，并让发布工作流把 Release 建到那里（需要一个对该仓库有写权限的令牌作为 secret，替换 `gh release create` 用的 `github.token`）。

工作流的配对检查：有私钥没公钥时失败；推送标签时有公钥没私钥也失败（否则这个版本的更新包没有签名，已安装的用户收不到）。

### 每次发布

- [ ] 改 `Cargo.toml` 的 `[workspace.package] version`（例如 `0.2.0`），合并到 main。
- [ ] 打标签 `v0.2.0` 并推送；`release` 工作流检查标签与版本一致，构建、静默安装检查（`kinshoko.exe` 与 `DirectML.dll` 都在安装目录），建一个**草稿** Release，附件为安装包、`.sig` 与 `latest.json`，说明文字是 [安装说明](../install.md) 加自动生成的变更列表。
- [ ] 下载草稿里的安装包，在**没有开发环境的 Windows**（例如新建的 Windows 沙盒或干净的虚拟机）上以普通用户安装：不出现管理员确认；SmartScreen 提示按 [安装说明](../install.md) 点“仍要运行”后能装上；启动后能建库、导入、看图；打标能用（DirectML 或 CPU）。
- [ ] 在 GitHub 上发布这个草稿 Release（发布前 updater 看不到它）。
- [ ] 装着上一版的电脑上打开 Kinshoko：主窗口底部提示新版本；“安装并重启”后自动退出、静默安装、重新打开，主窗口底部状态栏的版本号是新版本；钉图位置保留。
- [ ] “设置 → 更新 → 检查更新”显示“已是最新版本”。

### 诊断（#70）

- [ ] “设置 → 诊断 → 显示诊断信息”列出系统、处理器、内存、显卡、WebView2 版本、每台显示器的型号、分辨率、缩放、SDR／自动色彩管理／HDR 与配置文件名称；全文没有用户名、路径与文件名。在开着 HDR 或自动色彩管理的显示器上各看一次模式是否正确。
- [ ] 打开“强制 sRGB”：设置里提示重启生效，当前窗口颜色不变；从托盘退出再启动后，任务管理器“详细信息”里 `msedgewebview2.exe` 的命令行带 `--force-color-profile=srgb`，诊断信息里“强制 sRGB：已开启”。在广色域显示器上，广色域测试图在强制 sRGB 下变得更艳（不再按显示器配置文件转换）。关掉后再重启恢复。
- [ ] 使用日志默认关闭；打开后导入、查找、截图、钉图、贴边隐藏各做一次，“导出使用日志…”得到的文件每行只有时间、动作名与数量；关闭后不再增加；“清除使用日志”后导出为空。

## 画师电脑：缩小对比（#48，验收约定“图片还原度”一节）

发布前必须完成一次，结果决定缩略图的默认缩小方式。

1. 从 CI 的 `downscale-probe` 工作流下载 artifact `kinshoko-downscale-probe-<提交>`，整个文件夹发给画师。
2. 画师在平时作画的显示器设置下双击 `kinshoko-downscale-probe.exe`，按 `使用说明.md` 做完 26 组，点“保存报告”，把桌面上的 `kinshoko-缩小对比报告-<数字>.zip` 发回。
3. 开发者看 `报告.md` 的计数与留言，把结果填进验收约定“图片还原度”一节的表格。
4. 只有画师明确更偏好编码值空间时才改默认值：把 `crates/kinshoko-core/src/fidelity/render.rs` 的 `DEFAULT_DOWNSCALE` 改成 `Downscale::EncodedValue`，并改 `crates/kinshoko-core/tests/downscale.rs` 里写着默认值的测试。缩略图管线版本随之变为 `v1-encoded`，旧缩略图在打开资料库时作废、按需重建。偏好线性光或看不出区别时保持现状。

- [ ] 已收到画师的报告（日期、显示器、缩放比例）：
- [ ] 结果已补记到验收约定，默认值：线性光／编码值空间（划掉一个）

## 画师电脑（验收约定“桌面钉图”一节）

画师在优动漫中正常绘画约 30 分钟，用截图钉住 2～3 张网上找的参考，再钉 1 个库内局部。在 **WinTab** 与 **Windows Ink** 两种数位板模式下分别记录：

| 门槛 | WinTab | Windows Ink |
|---|---|---|
| 钉图始终位于优动漫上层，包括优动漫全屏时 | | |
| 优动漫或钉图有焦点时按贴边隐藏键，全部钉图收到屏幕边、只露细边；数位笔随即能在画布上作画 | | |
| 再按一次，钉图回到原位 | | |
| 数位笔能拖动、缩放钉图 | | |
| 数位笔能打开钉图右键菜单（侧键或按住），翻转、旋转、透明度、锁定都能用；锁定后笔拖不动、缩放不了 | | |
| 缩放与贴边滑动不一抖一抖（#7 的反馈） | | |
| SDR 桌面上，截图钉图未缩放、未翻转旋转时像素与截取时屏幕一致 | | |
| 重新打开后恢复钉图位置、裁切、翻转与旋转 | | |
| 全局快捷键与优动漫冲突时能更换 | | |

清晰度、动画手感、单张滑出是否顺手属于定性反馈，记在备注里，不作门槛。

## 开发机：库内整图与局部钉图（#65）

在开发机上用一个含下列图的资料库运行 `kinshoko.exe`（不要同时开着别的 kinshoko.exe）：一张普通 sRGB 图、一张广色域（Display P3 或 Adobe RGB 配置文件）图、一张动图（GIF 或动态 WebP）、一张 HDR 图（PQ／HLG 的 AVIF 或 HEIF），以及一张分级为成人内容的图。

- [ ] 查看器里“钉住整图”：钉图以图在查看器里的位置为中心、略微错开出现；大于显示器五分之三的图缩小显示
- [ ] Shift+拖动（或“框选局部”后拖动）框出局部，标签为“宽 × 高 px（原图像素）”；查看器缩放、平移后选区仍框着同一块；Enter 或“钉住局部”钉住
- [ ] 局部钉图未缩放时与原图同一块逐像素一致；拖动、滚轮缩放、角落缩放、H／V 翻转、R／Shift+R 旋转之后边界不变，没有露出局部以外的像素
- [ ] 缩小局部钉图约 1 秒后画面变清晰（换成精确尺寸的派生图）；放回 100% 时与原图逐像素一致
- [ ] 普通 SDR 显示器、未开 Windows 自动色彩管理：广色域图的钉图饱和色与查看器 1:1 显示一致，没有被裁到 sRGB（与 Photoshop 对照）
- [ ] 动图、HDR 图的钉图显示静止的 `sdr` 派生图，与查看器 1:1 相同
- [ ] 安全模式开启：从全年龄图钉住的钉图不遮蔽；在查看器关掉安全模式、钉住成人图、再开启安全模式，钉图立即原位模糊并显示小圆锁，不移走
- [ ] 点小圆锁、确认“显示”（或右键菜单“显示这张图”）：只这一张的模糊约 0.4 秒淡出；关掉安全模式后所有资料库钉图都不遮蔽；再开启时又全部遮蔽
- [ ] 改分级使图变成成人内容（安全模式开启时）：钉图随即遮蔽
- [ ] 退出后重新打开：资料库钉图恢复位置、局部、缩放、翻转、旋转、透明度与锁定；被封印的图重新遮蔽
- [ ] 切换到另一个资料库后，原库的钉图照常显示（自 #66 起未激活的已登记资料库只读读取），被封印的图仍遮蔽；取消登记原库后，钉图写出“本设备没有登记这个资料库”，摆放不丢

已知限制：查看器里没有 F1 框选（F1 是全局截图快捷键）；资料库钉图的右键菜单没有“复制”。

## 开发机：参考组（#66）

准备两个已登记的资料库 A、B（B 放在移动盘或可改名的文件夹里），各有几张图，其中 B 有一张分级为成人内容的图。不要同时开着别的 kinshoko.exe。

- [ ] 在 A 里钉一张整图、框一块局部；切换到 B 再钉两张（含成人图，安全模式关着时钉）；摆好位置、缩放、翻转、旋转，改透明度、锁定一张
- [ ] 主窗口“参考组”面板输入名称，“把桌面钉图存为参考组”：列表出现它，“4 个成员 · A、B”；截图钉图不进组
- [ ] 关掉全部钉图，“钉到桌面”：四个成员按存时的局部、位置、尺寸、缩放、翻转与旋转钉回；透明度、锁定不随参考组（钉出来不透明、未锁定）；再点一次不重复钉
- [ ] 当前活动库是 A 时，B 的成员照样显示（不切换活动库）
- [ ] 把同一张图的另一块局部存进第二个参考组；改动、存回第二个参考组后，第一个参考组打开仍是原来的局部与摆放
- [ ] 移动一个来自参考组的钉图，右键“存回参考组「…」”：再打开时在新位置；“存入桌面钉图”把别的钉图加为新成员
- [ ] 重命名、删除（要再点“确认删除”）都能用；删除后桌面上的钉图留着
- [ ] 安全模式开启后打开参考组：成人图原位模糊并显示小圆锁，布局不变；点小圆锁确认只显示这一张；“成员”列表写“安全模式下原位遮蔽”
- [ ] 拔掉移动盘（或把 B 的文件夹改名）后打开参考组：B 的成员仍按原布局钉出，钉图写出“资料库暂时不可用：…”；“成员”列表写出同样原因；接回后重新打开即可显示
- [ ] 取消登记 B 后打开参考组：B 的成员写“本设备没有登记这个资料库”
- [ ] 删掉 A 里某张图的原文件（模拟永久删除前的缺失）后，对应成员写“原图文件缺失”，布局保留
- [ ] 参考组文件在 `%APPDATA%\dev.kinshoko\reference-groups\<id>.json`，`format` 为 `kinshoko.reference-group`、`formatVersion` 为 1，不在任何资料库文件夹里

已知限制：保存参考组时，未收藏的截图直接跳过（规格 Q70 的“选资料库或不进组”逐张选择留给后续）；面板只列成员的资料库与局部尺寸，不显示缩略图；未激活资料库的派生图缓存写在该库的 `cache/` 下。
