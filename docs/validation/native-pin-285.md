# 原生钉图行为验收（#285）

2026-10-26，Windows 11，主显示器 2560×1440、显示缩放 110%，release 构建的测试实例（identifier `dev.kinshoko.pintest`、独立 `KINSHOKO_DATA_DIR`，`settings.json` 里 `"nativePins": true`）。没有截图进仓库。

## 逐帧核对 `pin-frame-check --app`

阶段：一格一帧放大到比屏幕大再缩回、每帧三格、隔 150 ms 一格、拖动、拖出屏幕一半再拖回、拖角放大再缩回、F4 收起→碰细边滑出→离开收回→F4 回原位。

| 项 | 结果 |
| --- | --- |
| 取到／核对 | 759 帧／545 帧 |
| 外框与边框都对上某次提交 | 400 |
| 外框对上（被裁过） | 130 |
| **外框对不上任何提交** | **0** |
| 应看得见却没有品红 | 0 |
| 画面倒退 | 0 |
| 滚轮格（应用收到／工具送出） | 84／84，没有一格落到前台窗口 |
| 前台始终是收键窗口 | 通过 |
| F4 | 贴边前、回来都是 (276, 255, 408×612)，收起时只露细边 |

先前几轮核对报“滚轮格落到前台窗口”，查下来是核对工具的问题：应用第一次提交时钉图还没显示（图读好、画好约 0.3 秒后才显示），工具在那之前就开始滚，头几格落到了钉图底下的窗口。工具改为等钉图窗口真出现在光标下再开始。快滚过程中没有丢格：低级鼠标钩子看到 84 格，应用收到 84 格。

## 探针（显示缩放 110%）

两个探针的截屏改用核对工具的桌面复制（`pin-frame-check --grab`）：GDI 截屏拍不到 DirectComposition 窗口。

- `capture_pin.py` 5／5 通过，含“钉图显示的像素与截图一致”（逐像素）。
- `edge_restore.py` 13／13 通过：点钉图与按键时前台不变；F4 只露 6 像素细边、收起时点击穿过、碰细边滑出、离开收回、再按 F4 回原位；H 翻转、R 旋转的屏幕像素与截图一致；结束进程再启动后位置、翻转、旋转都恢复。

探针查出一处与钉图层不一致：框选窗口关掉时系统把激活交还给原来的窗口，它若是置顶窗口（探针的测试图窗口就是）就盖住了新钉图。现在框选收尾后等隐藏与交还激活做完，再把新钉图放到最上面。
