# 首个本地版本的验收约定

2026-10-04。来源：[#4 确定首个本地版本的验收样本与指标](https://github.com/Yukk1No/kinshoko/issues/4) 的第十一轮访谈（Q44～Q67，记录见 [alignment.md](../discovery/alignment.md#第十一轮已确认)）。本文供 [#6](https://github.com/Yukk1No/kinshoko/issues/6)、[#7](https://github.com/Yukk1No/kinshoko/issues/7)、[#8](https://github.com/Yukk1No/kinshoko/issues/8) 等原型使用，不是实现规格；表中数值均为尚未实测的假设，原型结果可以修正，修正前后两版都要保留。

## 验收原则

- **客观门槛与定性反馈分开。** 能复现的项目写成门槛，跑之前确定；交互体验由画师试用给出定性反馈，作为迭代输入，不作通过与否的判断。
- **交互体验先按最佳实践做，再迭代。** 项目没有测试用户群体，首版不对找参考时间或体验做定量验收。画师找参考的方式是筛选后浏览、看到合适的再选取，“找到一张图花多久”不作指标。
- **只记录的项目不设门槛。** 后台耗时、容量等数据照实记录，用于后续比较与规格。
- **每份结论分三档：** 可用／需改进／尚未验证，并写明依据与仍未覆盖的部分。

## 硬件与环境基线

| 项目 | 约定 |
|---|---|
| 验收机器 | 画师实际绘画的电脑：AMD 独显、单显示器、绘王数位板、优动漫。CPU、内存、GPU 型号、分辨率与系统缩放在首次试用时记录 |
| 降级档 | 同一台机器强制 CPU 推理；没有独显时允许体验降级，例如换较小模型或打标较慢 |
| 开发机 | 用于反复运行与 100%／150% 缩放复测，结果不作验收依据 |
| GPU 路线 | 产品只走 ONNX Runtime + DirectML／Windows ML。ZLUDA 等 CUDA 兼容层不进产品，可作个人机器的附加实验 |

## 样本

- 来源为 pixiv 等站点的公开作品，以及构造的 Eagle 样本；覆盖不足时再补画师电脑中的小批真实素材（Q44）。
- 规模 200～300 张，覆盖单人／多人、头像／全身、遮挡、线稿、厚涂、灰度、复杂光照、局部裁切、极长图、透明图，以及常用发色、发长、齐刘海与中分。
- 另含约 30 张 R-18 作品，分 questionable 与 explicit 两档，用于分级验收；这部分由发起者自行下载。
- 图片不能再分发，仓库只提交[样本清单](sample-manifest.schema.json)：作品 ID、页码、SHA-256、覆盖维度、pixiv 作者标签和 R-18 标记。原图放在仓库外，或放在已忽略的 `samples/` 目录，由脚本按清单校验。
- 不做人工标签标注。pixiv 作者标签与 R-18 标记作为免费的弱真值。
- 社区贡献者按同一清单格式建立自己的样本；跨机器结果只比较流程，不比较数值。
- Eagle 样本在画师电脑的 Eagle 中构造：一图多文件夹、标签、URL、备注、区域评论，以及两个资料库含相同原图。

## 导入与数据保护（#8）

客观门槛，全部通过才算可用：

- 约定字段清单上的每一项往返后完全一致；字段清单由 #8 提交，发起者评审。
- 原文件 SHA-256 在导入、备份、恢复、组包往返后一致。
- 一次写入中断和一次部分失败都能按 Q38 重试：保留成功项，不重复创建记录。
- 备份范围按 Q43 计算，A/B、B/C 关联链结果可核对。

只记录：导入、备份、恢复耗时，备份容量。

画师反馈：恢复后浏览确认素材与参考组都在。

## 自动标签与内容分级（#6）

模型选型跟随社区：默认 PixAI v0.9，WD SwinV2 v3 作后备。#6 回答“PixAI 能否在验收机器上以可接受的方式运行”，不再证明哪个模型最好。

1. **首个实验**：PixAI 导出 ONNX，在 AMD 显卡上用 DirectML 运行；核对与 CPU 结果一致，确认没有算子静默回落 CPU。导出失败时，GPU 档先用 WD 官方 ONNX，PixAI 只在 CPU 档提供。
2. **选定条件**：能运行、分级达标、对照报告没有明显问题时选定 PixAI；否则退到 WD；两者都不满足时回到 [#9](https://github.com/Yukk1No/kinshoko/issues/9)。

客观门槛：

| 项目 | 假设门槛 | 依据 |
|---|---|---|
| 分级漏判 | 以 pixiv R-18 标记为真值，questionable＋explicit 的召回率 ≥ 95% | 漏判会让 R-18 图在安全模式下露出；宁可多模糊 |

只记录：

- 发色、发型等标签与 pixiv 作者标签的对照报告，用于发现几乎不出现或明显错位的标签。作者标签本身有遗漏，不作严格真值。
- 已知词表缺口，例如 WD v3 没有 `middle_part`。
- 分级误判为 R-18 的比例。
- 每档硬件的首次加载、单张推理 p50／p95、300 张批量总耗时、峰值 RAM／VRAM，以及打标期间优动漫是否卡顿。首次自动打标允许较慢（Q45）。

画师反馈：约 12 条查询，其中约 8 条来自画师最近的真实需求；另补单条件、2～3 条件组合、含排除、中分与中文别名各一类，分别标注来源。每条查询回答“筛选后这一屏值得刷吗”：值得／一般／不值得。

## 桌面钉图（#7）

先依据[参考板实践调查](../research/reference-board-practices.md)及 PureRef 一类工具的常见做法，定出打开、锁定、穿透切换和退出方式，再做原型。

客观门槛：画师在优动漫中正常绘画约 30 分钟，钉 2～3 个局部。以下各项在 WinTab 与 Windows Ink 两种数位板模式下分别通过／不通过：

- 钉图始终位于优动漫上层，包括优动漫全屏时。
- 开启鼠标穿透后，数位笔笔触落到画布。
- 能可靠退出穿透。
- 局部清晰，边界不随移动或缩放改变；开发机另在 100% 与 150% 缩放下复测。
- 重新打开后恢复钉图位置与裁切。

清晰度由画师对照 1:1 原图判断。其他品牌、多显示器、混合缩放和其他绘画软件进入[兼容性矩阵](../../.github/ISSUE_TEMPLATE/compatibility.yml)，由社区填报，不作首版门槛。

## 交互响应

采用通用响应标准，不与 Eagle 对比：搜索出结果、滚动、打开原图、钉图都应让人感觉不到等待；操作反馈约 100 ms 内出现，滚动不出现白块。具体数值随 #6、#13 原型的实测细化。

## 内容分级与安全模式

首版提供全局安全模式开关，覆盖浏览、搜索、参考组和钉图。开启时模糊 questionable 与 explicit，位置保留，点开前需要确认；新安装默认开启，可用快捷键切换。分级沿用自动建议加人工修正的规则，人工决定优先。验收见上文“分级漏判”。

## 反馈渠道

- 原型提供默认关闭的“记录使用日志”开关：搜索条件、打开与钉住的图片只写入本地文件，由画师自行决定是否导出。不作为正式产品的开发模式，不做默认上传的遥测。
- 社区通过 Issue 模板提交交互反馈、标签识别错误和兼容性结果。
- 人工纠正数据的自愿导出进入 roadmap。
