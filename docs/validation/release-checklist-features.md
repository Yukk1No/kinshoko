# 发布前检查清单：功能逐项

[发布前检查清单](release-checklist.md)的后半部分：各功能在开发机与画师电脑上的逐项检查。

## 开发机：库内整图与局部钉图（#65）

在开发机上用一个含下列图的资料库运行 `kinshoko.exe`（不要同时开着别的 kinshoko.exe）：一张普通 sRGB 图、一张广色域（Display P3 或 Adobe RGB 配置文件）图、一张动图（GIF 或动态 WebP）、一张 HDR 图（PQ／HLG 的 AVIF 或 HEIF），以及一张分级为成人内容的图。

- [ ] 查看器里“钉住整图”：钉图以图在查看器里的位置为中心、略微错开出现；大于显示器五分之三的图缩小显示
- [ ] Shift+拖动（或“框选局部”后拖动）框出局部，标签为“宽 × 高 px（原图像素）”；查看器缩放、平移后选区仍框着同一块；Enter 或“钉住局部”钉住
- [ ] 局部钉图未缩放时与原图同一块逐像素一致；拖动、滚轮缩放、角落缩放、H／V 翻转、R／Shift+R 旋转之后边界不变，没有露出局部以外的像素
- [ ] 缩小局部钉图约 1 秒后画面变清晰（换成精确尺寸的派生图）；放回 100% 时与原图逐像素一致
- [ ] 普通 SDR 显示器、未开 Windows 自动色彩管理：广色域图的钉图饱和色与查看器 1:1 显示一致，没有被裁到 sRGB（与 Photoshop 对照）
- [ ] 动图、HDR 图的钉图显示静止的 `sdr` 派生图，与查看器 1:1 相同
- [ ] 安全模式开启：从全年龄图钉住的钉图不遮蔽；在查看器关掉安全模式、钉住成人图、再开启安全模式，钉图立即原位模糊并显示小圆锁，不移走
- [ ] 点小圆锁、确认“显示”（或右键菜单“显示这张图”）：只这一张的模糊约 0.4 秒淡出；关掉安全模式后所有资料库钉图都不遮蔽；再开启时又全部遮蔽
- [ ] 改分级使图变成成人内容（安全模式开启时）：钉图随即遮蔽
- [ ] 退出后重新打开：资料库钉图恢复位置、局部、缩放、翻转、旋转、透明度与锁定；被封印的图重新遮蔽
- [ ] 切换到另一个资料库后，原库的钉图照常显示（自 #66 起未激活的已登记资料库只读读取），被封印的图仍遮蔽；取消登记原库后，钉图写出“本设备没有登记这个资料库”，摆放不丢

- [ ] F1 框在查看器已显示的图内：钉出的局部仍引用原库与原图，裁切按原图像素记，不进入截图历史；缩放、平移、不同 DPI 下重复核对
- [ ] F1 框在已有局部钉图内（含翻转、旋转）：新局部仍引用同一原图；框在其他应用或跨出图外时仍得到截图；检查被其他窗口遮挡、贴边隐藏与动画中的情况

- [ ] 资料库钉图右键“复制”：剪贴板里是钉图显示的那一块原图像素（局部、翻转、旋转照钉图）；被遮蔽时“复制”变灰
- [ ] 读不到图的钉图（资料库不可用、本设备没有登记、原图缺失）显示中性灰占位与原因文字；资料库回来后重新打开参考组或切回资料库，占位换成图

F1 的坐标换算与查看器来源报告有自动测试，钉图窗口遮挡、DPI 和输入交互仍需执行以上真机检查。钉图本身的检查（逐帧核对、动画、多显示器、设备丢失）见[钉图部分](release-checklist-pins.md)。

## 开发机：参考组（#66）

准备两个已登记的资料库 A、B（B 放在移动盘或可改名的文件夹里），各有几张图，其中 B 有一张分级为成人内容的图。不要同时开着别的 kinshoko.exe。

- [ ] 在 A 里钉一张整图、框一块局部；切换到 B 再钉两张（含成人图，安全模式关着时钉）；摆好位置、缩放、翻转、旋转，改透明度、锁定一张
- [ ] 主窗口“参考组”面板输入名称，“把桌面钉图存为参考组”：列表出现它，“4 个成员 · A、B”
- [ ] 桌面上还有截图时，保存前逐张列出：为一张选 A 收藏、另一张选“不加入参考组”；确认后只加入选中的截图，保留裁切与摆放；取消不保存参考组
- [ ] 一张截图选“只存在参考组里”保存：图库和瀑布流里没有它；关掉钉图、截图历史清空后重新“摆到桌面”，它按原布局钉出；从参考组移出它或删除参考组后，`reference-groups/<参考组>.captures/` 里的文件随之删除；导出参考组包再导入，它还在（#270）
- [ ] 在钉图菜单里“收藏”一张来自参考组的截图：成员改为引用图库里的参考图，组内那份文件删除（#270）
- [ ] 只存在参考组里后关掉钉图，再从截图历史“收藏”这张截图：参考组成员改为引用图库里的参考图，组内那份文件删除（#270）
- [ ] 先手动收藏截图再存组：该截图仍列出，可选择已收藏的库，入组后钉图连接原图；之后移动并“存回参考组”能更新原成员
- [ ] 关掉全部钉图，“钉到桌面”：四个成员按存时的局部、位置、尺寸、缩放、翻转与旋转钉回；透明度、锁定不随参考组（钉出来不透明、未锁定）；再点一次不重复钉
- [ ] 当前活动库是 A 时，B 的成员照样显示（不切换活动库）
- [ ] 把同一张图的另一块局部存进第二个参考组；改动、存回第二个参考组后，第一个参考组打开仍是原来的局部与摆放
- [ ] 移动一个来自参考组的钉图，右键“存回参考组「…」”：再打开时在新位置；“存入桌面钉图”把别的钉图加为新成员
- [ ] 重命名、删除（要再点“确认删除”）都能用；删除后桌面上的钉图留着
- [ ] 安全模式开启后打开参考组：成人图原位模糊并显示小圆锁，布局不变；点小圆锁确认只显示这一张；“成员”列表写“安全模式下原位遮蔽”
- [ ] 拔掉移动盘（或把 B 的文件夹改名）后打开参考组：B 的成员仍按原布局钉出，钉图写出“资料库暂时不可用：…”；“成员”列表写出同样原因；接回后重新打开即可显示
- [ ] 取消登记 B 后打开参考组：B 的成员写“本设备没有登记这个资料库”
- [ ] 删掉 A 里某张图的原文件（模拟永久删除前的缺失）后，对应成员写“原图文件缺失”，布局保留
- [ ] 参考组文件在安装目录的 `data\reference-groups\<id>.json`，`format` 为 `kinshoko.reference-group`、`formatVersion` 为 1，不在任何资料库文件夹里

已知限制：面板只列成员的资料库与局部尺寸，不显示缩略图；未激活资料库的派生图缓存写在该库的 `cache/` 下。

## 开发机：标签整理（#77 UI-B，#51）

发布构建，准备一个已有几张图、已有模型自动标签的资料库，其中一张分级为成人内容。不要同时开着别的 kinshoko.exe。

- [ ] 选中一张图：整理面板“有效标签”列出标签与出处（“模型 0.92”“Eagle”“人工添加”）；尚未翻译的显示“文A”，没有外部对应的显示提示图标
- [ ] 点“⊘”否决一个模型标签：它移到“已否决”（划线）；“撤销否决”后回到模型建议；点“✓”确认后标出“人工添加”，“清除”后回到来源决定的状态
- [ ] 命名空间选“作者”、输入名称“添加标签”，再用同一名称加一个“一般”标签：列出“作者：…”与“…”两个标签
- [ ] Ctrl 点选多张图，输入标签名“添加标签”／“否决标签”：每张图都记下决定；侧栏分组计数与搜索框候选随即更新
- [ ] 对一个标签点“别名”加一个叫法：别名列表出现它；搜索框输入别名时候选写“又名：…”；“添加标签”输入别名落到原标签上，不新建
- [ ] 侧栏“标签分组”点“＋”建一个“自己挑选的标签”分组，再用“＋”从库内标签挑成员：侧栏列出标签与张数；点标签只看有这个标签的图，点分组名看有分组中任一标签的图
- [ ] 双击分组名改名、“×”移出成员、删除分组都生效；建一个“全部作品”分组，列出作品命名空间的全部标签
- [ ] 打开安全模式：只在成人图上的标签不出现在整理面板候选、侧栏分组与搜索候选中，分组计数不含成人图；关闭后它们回来，分组里原有的成员没丢
- [ ] 退出后重新打开：标签决定、别名、分组及其成员都在
- [ ] 让模型重新打标（换模型或删掉模型层后重打）：否决的标签仍不出现，人工添加的仍在

## 开发机：参考组包（#68）

往返检查（原图 SHA-256、同一原图只带一次、不带其他素材、快照、另存为新组、损坏的包不写入）已是核心 crate 测试 `crates/kinshoko-core/tests/reference_group_package.rs`。这里只看界面与真实文件。

- [ ] 用一个跨 A、B 两库、含同图两块局部的参考组点“导出参考组包”：保存对话框默认文件名是“<组名>.kinshoko-group”；包可用解压软件打开，只有 `manifest.json` 与 `originals/` 下所用的原图
- [ ] B 不可用时导出：提示哪些成员取不到原图，不写包
- [ ] 在另一台电脑（或另设 `KINSHOKO_DATA_DIR` 的全新数据目录）新建资料库后“导入参考组包”：列表出现同名参考组；“钉到桌面”的局部、位置、缩放、翻转与旋转与导出前一致；原图进了当前资料库，标签、备注、来源链接与分级随快照带来，备注标为来自参考组包
- [ ] 两个来源库用同字节原图但标签、备注、分级不同：导入后原图只存一份，两套来源信息都保留；任一来源为成人分级时仍遮蔽；自定的多语言名称和全部外部对应保留，目标库已有整理不被覆盖
- [ ] 安全模式开启时导入含成人图的包：这些图在浏览中不出现，钉到桌面原位遮蔽
- [ ] 同一个包再导入一次：多一个参考组，资料库里不多出重复的图

已知限制：导出、导入在后台一次完成，没有进度条；包内只有导出时的快照，不反向更新来源库，也不自动恢复整个来源库。

## 开发机与画师电脑：本地备份与恢复（#69）

准备两个已登记的资料库 A、B（各有几张图、文件夹、备注、标签、个人近似对应表条目，A 有一张在回收站里），一个跨 A、B 的参考组和一个只引用 A 的参考组；一块移动盘或 U 盘作备份目标。不要同时开着别的 kinshoko.exe。范围计算、增量复制、租约、保留策略、恢复与往返检查已由 `crates/kinshoko-core/tests/backup_*.rs` 覆盖，这里只查要真机与真时间的部分。

- [ ] 设置 →“备份”→“选择备份目录…”选移动盘上的文件夹：显示“备份到 …”；“马上备份”显示“正在备份：原图 n／m”，完成后“上次备份”是现在的本地时间；移动盘上出现 `kinshoko-backup\snapshots\<日期-时间-…>\manifest.json` 与 `kinshoko-backup\originals\`
- [ ] 选“只备份所选资料库”只勾 A：列出带上的参考组与容量；取消“一起备份参考组还引用的资料库”后列出“参考组「…」引用的「B」不在这次备份里”
- [ ] 再导入一张图后“马上备份”：很快完成，`originals` 下只多出一个文件
- [ ] 原文件复制期间新增图并存入已有参考组：本次备份恢复后仍使用备份开始时的组引用，往返检查通过（公共接口并发回归已覆盖）
- [ ] 备份进行中在 A 的回收站里永久删除一张图：备份完成且完整；之后重开 A，原文件才从 `originals\` 消失
- [ ] 当天第二次关闭主窗口不再自动备份；把系统日期调到第二天（或等到第二天）后第一次关闭主窗口，托盘提示“正在备份…”，主窗口重开后“上次备份”更新
- [ ] 不碰键盘、鼠标与笔 10 分钟以上（当天还没备份时）：自动备份一次
- [ ] 拔掉移动盘后托盘“退出”：进程很快结束；重新启动后主窗口底部提醒“备份没有完成：备份目标不在……下次退出或空闲时再试”，设置里也写出原因；接回移动盘、下次关闭主窗口后自动备份成功，提醒消失
- [ ] 托盘“退出”（当天还没备份、移动盘在）：先备份完再结束进程
- [ ] “从备份恢复…”选一个快照、选一个空文件夹：显示“往返检查通过：原图 … 张哈希一致、整理信息 … 张表、参考组 … 个一致”；资料库列表多出“A（恢复）”“B（恢复）”，活动资料库没变；参考组列表多出同名的新参考组，打开后成员来自恢复出的库（局部与摆放不变）；原来的资料库与参考组不变
- [ ] 切换到“A（恢复）”：图片、文件夹、备注、标签、回收站与个人近似对应表都在；原图 1:1 显示正常
- [ ] **画师确认**（验收约定“导入与数据保护”）：在画师电脑上对真实资料库备份到另一块盘、恢复，浏览确认素材与参考组都在，记下备份与恢复耗时、备份容量

已知限制：备份目标只支持本地目录（含移动盘）；备份目录不在时不会改备份到别处；读不到的资料库（例如所在移动盘没插）这次跳过并在结果里列出，快照仍算完整；恢复出的资料库名称加“（恢复）”，文件夹名加恢复日期。
