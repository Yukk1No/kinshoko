# 发布前检查清单：桌面钉图

[发布前检查清单](release-checklist.md)的钉图部分。钉图是每张一个原生窗口、wgpu 绘制（[ADR 0013](../adr/0013-native-pin-windows-wgpu.md)，#277）；钉图菜单、F1 框选窗口与遮蔽的“确认显示”仍是 WebView 窗口。库内钉图、参考组的逐项检查在[功能逐项](release-checklist-features.md)。上一次的结果：[#284](native-pin-284.md)、[#285](native-pin-285.md)、[#287](native-pin-287.md)。

## 准备：测试实例

开发机上的脚本用独立的数据目录与 identifier 起一个测试实例，不碰本机设置与资料库：

```bash
npx tauri build --no-bundle --config '{"identifier":"dev.kinshoko.pintest"}'
```

```bash
cd tools/pin-frame-check && cargo build --release
```

- 运行期间不要碰键鼠。脚本会弹出钉图、最大化的测试用 Edge，动真实鼠标键盘。
- 先退出本机装着的 Kinshoko 和别的占用 F1／F3／F4 的程序（例如 Snipaste）：脚本按默认快捷键操作，Kinshoko 是单实例。
- 主显示器的颜色配置文件要是 sRGB（或没有）：逐帧核对靠纯品红认边框。
- 屏幕截图只截钉图那一块（`pin-frame-check --grab`，桌面复制；GDI 截屏拍不到原生钉图），全桌面截图不进仓库。

## 开发机：脚本检查

100%、125%、150% 显示缩放各跑一遍，填通过／不通过与关键数字。

| 检查 | 命令 | 通过标准 | 100% | 125% | 150% |
|---|---|---|---|---|---|
| 逐帧核对（#283～#285） | 测试实例以 `KINSHOKO_DATA_DIR`、`KINSHOKO_PIN_TRACE` 启动（命令见 [pin-frame-check](../../tools/pin-frame-check/README.md)），再 `tools/pin-frame-check/target/release/kinshoko-pin-frame-check.exe --app <trace> <报告.txt>` | 报告里“外框对不上任何提交”为 0、“应看得见却没有品红”为 0、“画面倒退”为 0，滚轮格应用收到等于工具送出，前台始终是收键窗口，核对帧数不为 0 | | | |
| 截图钉图逐像素一致（#62） | `python scripts/probe/capture_pin.py target/release/kinshoko.exe` | 全部 ✓ | | | |
| 贴边隐藏、交还焦点、碰细边滑出、收起时点击穿过、翻转旋转、重开恢复（#63、#64） | `python scripts/probe/edge_restore.py target/release/kinshoko.exe` | 全部 ✓ | | | |
| 背后的程序照常绘制、不触发全屏判定（#275） | `python scripts/probe/pin_backdrop.py target/release/kinshoko.exe` | 背后最大化的 Edge 在 1 张、8 张、缩放换窗中、一张盖满屏幕、钉图菜单开着、F1 框选中、Edge 全屏时都 `visible`，rAF 不低于没有钉图时的 90%；Kinshoko 主窗口最大化在钉图背后同样；钉图盖满屏幕时 QUNS 不是 BUSY；前台不被钉图抢走 | | | |
| 设备丢失后重新显示 | `python scripts/probe/pin_device_loss.py target/release/kinshoko.exe` | 重新显示 < 1000 ms，之后钉图与测试图逐像素一致、位置不变、滚轮能缩放，进程不退出 | | | |

非整数缩放（125%、150%）下钉图不被重新采样：`capture_pin.py`、`edge_restore.py` 的像素比较都要通过。`pin_device_loss.py` 用测试钩子 `KINSHOKO_PIN_LOSE_DEVICE_MS` 销毁 GPU 设备；真实的驱动重启、远程桌面切换见下面“真机：设备丢失”。

逐帧核对的工具本身由对照组证明能抓到错位：`pin-frame-check --selftest <报告> --verify --naive` 应当报出对不上的帧（`scripts/run-all.sh` 一起跑）。

## 开发机：门槛实验“钉图 vs 查看器 1:1”

```bash
node e2e/fidelity-gate.mjs target/release/kinshoko.exe <报告目录>
```

报告的“钉图离屏渲染 vs 正式派生图”一节：每个样本应用在 1:1 时显示的文件（与查看器 1:1 显示的是同一个文件）经钉图渲染层与显示器查找表画出，与 moxcms 直接转到主显示器配置文件的结果比较。记下 GPU、显示器配置文件、是否开着 Windows 自动色彩管理（ACM）。

- [ ] 普通 SDR 显示器、未开 ACM、显示器装着校准 ICC：计入门槛的样本最差色块 ΔE2000 < 1。开发机没有校准 ICC 时记 sRGB 下的结果；合成的校准 ICC（`calibrated_display_icc`）由 CI 的 `pin-render` 离屏测试覆盖。
- [ ] 开着 ACM 的显示器上跑一次，只记录（ACM 下系统把显示器当 sRGB 交给应用）。
- [ ] 查看器 1:1 与钉图 100% 并排目视同一张广色域图、一张 sRGB 图：看不出差别（画师电脑上也看一次）。

## 开发机：钉图右键菜单与动画（#64、#285）

发布构建，100%、125%、150% 各做一遍；鼠标与数位笔（Windows Ink、WinTab 两种模式）各做一遍：

- [ ] 鼠标右键弹出菜单；笔的侧键弹出菜单；笔尖或触摸按住钉图不动约半秒弹出菜单。同一次按下只弹一次。菜单收起后前台回到原来的程序。
- [ ] 菜单里水平翻转、垂直翻转、顺时针／逆时针旋转都生效，旋转时中心不动；光标在钉图上按 H、V、R、Shift+R 同样生效，光标不在钉图上时这些键照常交给绘画软件。
- [ ] 透明度子菜单 10%～100% 生效，当前值打勾；Ctrl+滚轮每格 10%。
- [ ] 勾选“锁定位置与大小”后，鼠标、笔都拖不动钉图，滚轮和右下角都缩放不了，“原始大小”变灰，仍能打开菜单；取消勾选后恢复。
- [ ] 透明度与锁定在结束进程再启动后恢复。
- [ ] 滚轮一格、连续快滚、拖右下角缩放、菜单“原始大小”都平滑过渡（约 0.14 秒）；动画中再滚一格或继续拖角时从当前位置接着走，不跳回起点；缩放停下约 0.1 秒后钉图清晰。
- [ ] 贴边收起、碰细边滑出、离开收回、再按 F4 回原位都是平滑滑动。
- [ ] 换窗的那一下（放大到超出原窗口、停手后窗口收回）钉图没有闪一下、跳一帧或露出别处的像素：收到左边、上边与从左边、上边回原位时，以及滚轮以光标为中心放大时注意看。出现时记下缩放比例与机器。
- [ ] 收起后细边旁边原本被钉图挡住的地方可以正常点到下面的程序（点击穿过）；滑出后钉图能拖动。
- [ ] 钉图四周一圈柔和投影，按在投影上等于按在钉图边上，投影以外点到下面的程序；“设置 → 增强钉图边缘”加一圈浅色细线，已钉着的钉图立即重画。
- [ ] 任务栏和 Alt+Tab 里看不到钉图窗口。
- [ ] 菜单“关闭”与光标在钉图上按 Esc 都能关掉；最后一张关掉后任务管理器里 Kinshoko 的 GPU 内存回落（不再持有 GPU 设备）。

## 开发机：数位笔（#63）

数位板驱动分别切到 **Windows Ink** 与 **WinTab** 模式，各做一遍：

- [ ] 用笔按住钉图拖动，钉图跟手移动。
- [ ] 用笔按住钉图右下角拖动，钉图缩放、左上角不动；拖动中跨过换窗（放大到超出原窗口）笔不断、松开后才停。
- [ ] 用笔点一下钉图后按 F4，钉图收到屏幕边，笔随即能在绘画软件里画，不需要先点一下绘画软件。
- [ ] 笔悬停碰到细边时钉图滑出，离开后收回。
- [ ] 笔侧键打开菜单；笔尖按住约半秒打开菜单。
- [ ] 截图框选区域里用笔拖动框选，不触发系统手势。

## 真机：多显示器与不同缩放比例

两台缩放比例不同的显示器（例如 100% 与 150%），最好其中一台是广色域或装着别的配置文件：

- [ ] 在两台显示器上各新建钉图（截图钉图、资料库钉图）：尺寸按物理像素，截图钉图回到截取的显示器上逐像素一致。
- [ ] 把钉图拖到另一台显示器、拖着跨过两台的交界：尺寸不随缩放比例跳变；中心过去后颜色换成那台显示器的转换（广色域显示器上饱和色不变暗、不发灰）。
- [ ] 跨屏时滚轮缩放、拖角缩放，横跨两台时贴边隐藏（F4）再回原位。
- [ ] 收到与相邻显示器相接的边时，收起的部分不出现在相邻显示器上挡住点击（记录现象）。
- [ ] 运行中改某台显示器的缩放比例、换颜色配置文件：钉图尺寸不变，颜色跟着换。
- [ ] 拔掉一台显示器：上面的钉图之后重新打开 Kinshoko 时拉回屏幕内（运行中拔掉不拉回，与以前相同，记录现象）；插回后照常。

## 真机：设备丢失

- [ ] 远程桌面连上这台电脑再断开回到本机（或锁屏切换用户再回来）：钉图在 1 秒左右重新显示，位置、缩放、透明度不变，之后能照常拖动缩放。“诊断信息 → 存成文件…”的运行日志里有“原生钉图 GPU 设备丢失”“设备丢失后重新显示 N ms”。
- [ ] 按 Win+Ctrl+Shift+B（重启显卡驱动，屏幕会黑一下）：同上。没有这两条日志、钉图也一直在，说明这次没丢设备，记录即可。

## 真机：核显与其他环境

- [ ] 一台只有核显（Intel UHD／Iris Xe 或 AMD 核显）的电脑：钉图能显示、拖动缩放跟手、换窗不闪；“设置 → 诊断”的显卡一行与钉图用的适配器一致。记下 GPU、驱动版本、钉 10 张常见尺寸钉图后任务管理器里的内存与 GPU 内存。
- [ ] Windows 10：点击穿过（贴边收起）开关前后钉图画面不变。
- [ ] Windows 设置“悬停时滚动非活动窗口”关掉时，滚轮是否还能缩放钉图（不能的话写进发布说明）。
- [ ] 一张钉图放大到盖满显示器时，Windows 不进“请勿打扰”（专注助手不自动打开，通知照常弹出）；Wallpaper Engine 在钉图背后不黑、不暂停。
- [ ] 手势中（到停手后约 0.1 秒）钉图外围透明处会接住点击：写进发布说明。
