# 首个本地版本的技术路线

2026-10-06。来源：[#9 根据验证结果确定首个本地版本的技术路线](https://github.com/Yukk1No/kinshoko/issues/9) 的 grilling（Q1～Q26）。这是交给 `/to-spec` 的决策摘要，不是实现规格；版本号与 schema 由规格和锁文件确定。术语见 [GLOSSARY](../../GLOSSARY.md)，难以回退的决定见 [ADR-0004](../adr/0004-tech-stack-and-process-model.md)、[ADR-0005](../adr/0005-two-path-display-pipeline.md)。

## 技术路线

| 项目 | 决定 | 已验证依据 | 剩余风险 |
|---|---|---|---|
| 框架 | Tauri 2 + Rust；React 19＋TS＋Vite；瀑布流沿用 #13 样稿自写的纯函数布局（尺寸取自资料库记录、最短列放置、二分查找可见范围加 overscan），不用 TanStack Virtual（#9 Q27：尺寸已知，TanStack 的测量与锚点修正只增加复杂度） | #7 钉图原型（[PR #21](https://github.com/Yukk1No/kinshoko/pull/21)）；#13 浏览样稿（[PR #25](https://github.com/Yukk1No/kinshoko/pull/25)、[PR #35](https://github.com/Yukk1No/kinshoko/pull/35)）；[#28](https://github.com/Yukk1No/kinshoko/pull/28) 字体 | release 包离线安装、无独显机器内存未实测；缩放与贴边动画不能逐帧调原生窗口，需另行设计 |

## 模块

Rust 侧六个模块加应用壳。用 codebase-design 的删除测试筛过，Library 接口经过三版并行设计后取混合方案。

- **Library**：资料库身份、参考图、元数据、标签与人工标签决定、个人近似对应表；独占 SQLite 写入。导入（暂存、校验、pending、发布、事务）在其内部，导入来源是真接缝：普通文件（含剪贴板与收藏截图）和 Eagle 两个 adapter。
  - 接口骨架按界面动作划分、强类型：`browse`、`image`、`edit`、`import`（返回可取消、带逐项结果的任务）、`sidebar`、`events`、`vocabulary`；打标和备份各有一个小的子接口。
  - 内部写入按来源分层：Eagle、模型等来源重写时只替换自己那一层，人工标签决定始终优先。同一条规则服务 Eagle 重导、重新打标，以及以后的合并与同步。
  - 安全模式在 Library 内部执行。`Lens` 分浏览与参考两种视角：浏览视角不返回被封印的图，也不计入计数和候选；参考视角返回并标记需要遮蔽。只有参考组与钉图在装配时拿到参考视角的句柄。
  - 永久删除两步：预览返回受影响的参考组（经由参考组用途 port，由参考组模块实现）和一个令牌，数据变化后令牌失效。
  - 修订号用于分页游标与令牌过期；内部留故障注入点，测试在各写入步骤模拟崩溃。SQLite 与文件系统不设接缝，测试用临时目录里的真库。
  - 不预留尚不存在功能的枚举变体（按颜色找图、相似图等），到时再加。
- **Search**：纯计算。输入、标签词表快照、内置与个人近似对应表 → 可见的条件树（别名、命名空间候选、近似展开）；Library 执行。
- **Tagging**：调度打标子进程，写入自动标签建议与内容分级建议。子进程与测试假实现是同一接缝上的两个 adapter；画师绘画时暂停等调度策略藏在内部。
- **ReferenceGroups**：独立保存的参考组与参考组成员、参考组包的导出与导入（[ADR-0002](../adr/0002-independent-reference-groups.md)）。
- **Backup**：范围计算、容量估计、快照、历史保留与恢复编排；只通过 Library 与 ReferenceGroups 提供的依赖清单与快照入口接触其存储，不认识磁盘布局。
- **Desktop**：截图、截图历史、桌面钉图窗口与状态、贴边隐藏、全局快捷键、托盘。钉图渲染器是可替换模块，HDR 时换 WebGPU。
- **应用壳**：本设备登记的资料库与设置；不单列模块。

前后端契约用 ts-rs 从 Rust 类型生成。

## 首版范围

首版一次性完整交付（[#3](https://github.com/Yukk1No/kinshoko/issues/3) 方向访谈），验收按[验收约定](../validation/acceptance.md)。

**进入首版**

- 收集：图片文件、文件夹、拖放、剪贴板、截图收藏。格式 JPEG、PNG、WebP、GIF；动图（GIF、动态 WebP、APNG）保留原文件、显示静态首帧；HDR 图片保留原文件、按 SDR 显示；不支持的格式逐文件报告。
- 自动标签建议与内容分级，人工修正优先；安全模式（封印书）。
- 基础检索：标签、文字、中文别名，默认同时满足，显式“或”与排除，命名空间候选。
- 近似查找，默认展开，可改回精确：
  - 内置近似对应表：脚本生成候选，由 LLM agent 审核后入表，首批覆盖发色、瞳色、发型、刘海四类，随软件分发、带版本，生成脚本留在 `tools/`。
  - 个人近似对应表：随资料库保存，按库内标签记录“相近”或“不相近”，优先于内置表。入口为搜索框展开结果中的“只这次／以后都不展开”和“＋”；资料库设置中列出条目、可删除；来源标记在设置中开启，默认不显示。完整管理界面以后迭代。
  - 没有外部对应的标签旁显示提示图标（与“尚未翻译”同一逻辑），说明它不参与内置近似对应表；Eagle 导入向导说明这一点。
- Eagle 导入：1.8.x 与 4.x，按字段是否存在解析，枚举以 `images/` 为准；导入时按名称与翻译表精确匹配外部对应，未匹配的标签列出，可手动补或跳过。区域评论只保证保存往返。
- 多资料库（建立、登记、切换；一次一个活动库），参考组与参考组包，参考组跨库引用。
- 截图钉图、截图历史、贴边隐藏与交还焦点；笔与鼠标共用 pointer 处理并禁止系统手势（#7）。
- 本地备份与恢复：
  - 目标：用户选择的本地目录（通常是另一块硬盘或移动盘）。
  - 频率：每天第一次退出或空闲时自动备份一次，可手动；目标不在时下次再试并提醒。
  - 方式：原文件按哈希增量复制，SQLite 用 Online Backup。
  - 历史：保留最近 7 份每日快照和 4 份每周快照。
  - 验收：恢复后跑 #8 的往返检查。

**留在 roadmap**：资料库合并（含标签决定冲突向导）、JEV 与 LLM 辅助查找、智能文件夹、按颜色找图、HDR 显示与采集、远端备份与持续同步、超分、网页收集与动态参考。

## 规格切分与第一颗 tracer bullet

首版写成一份 `/to-spec` 规格，再由 `/to-tickets` 拆成端到端可运行的 tracer-bullet 工单。

1. **建库 → 导入 → 瀑布流浏览与查看原图 → 关闭后重开**，带上图片管线的门槛实验（[核查](../research/image-fidelity-pipeline.md#尚未验证)），以及给画师的线性光／编码值空间缩小对比探测程序。
2. 之后依次接上自动标签、检索与近似查找、Eagle 导入、截图与钉图、参考组、安全模式、备份恢复。

## 仍需取得的事实
