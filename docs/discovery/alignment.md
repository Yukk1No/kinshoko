# 领域对齐记录

记录日期：2026-10-01。本文记录访谈中的共识与未决问题；当前尚未形成完整产品规格。

## 第一轮已确认

- **首个验收对象**：首位画师用户的 Windows 单人绘画工作流。
- **产品流程边界**：保存参考图 → 整理与检索 → 选择整图或局部 → 在绘画桌面使用。
- **最主要的痛点**：在自己的参考图库中找到需要的参考耗时最多，最妨碍绘画。
- **代表场景**：查找某种发色，或短发、长发、齐刘海、中分等发型；通过点击分类好的标签或输入文字找图，再截取需要的局部钉在桌面上。

以上首个验收对象用于验证阶段，未决定未来其他平台或使用群体的范围。

## 第二轮已确认

发起者明确接受 Q1～Q7 的推荐，并补充 Q8 的使用目标。

- **标签供给（Q4）**：自动提供标签建议，允许人工修正，并保留已有标签。
- **文字检索（Q5）**：首版让文字与点击标签表达同一组条件，支持中文别名与多个条件组合；自由描述检索另行验收。
- **局部参考（Q6）**：采用参考图加关联参考视图的概念；从同一张图选出眼睛和头发时形成两个视图，保留与来源参考图的关系。
- **Eagle 兼容（Q7）**：先把 Eagle 作为迁移来源，之后由 Kinshoko 独立管理图库；持续共用原库作为另一种接入需求。
- **存储与可靠性（Q8）**：本地使用是主要场景，素材备份与多设备同步必须进入 roadmap。发起者希望辛苦收集的素材在设备损坏后能恢复，换设备后仍可使用。具体规格尚未确定。
- **费用与扩展偏好（Q8）**：优先考虑免费方案或开放接口是发起者提出的方向；产品内置哪些流程、用户自行提供什么，仍需讨论。

## 第三轮反馈

- **Q9**：首个实用版本内置完整图库备份与恢复的提案，尚未得到单独、明确的确认。
- **持续同步（Q10）**：发起者指出换机恢复已被 Q9 覆盖；多设备同步必须表示设备间持续传递新增和修改，不能用一次性恢复代替。具体设备与同步规格仍在思考。
- **视图保存与参考组（Q11）**：发起者接受临时钉图与主动保存参考视图，并明确希望把多张图中的优秀局部组合起来，保存后整体复用。已记录“参考组”这一概念。保存成员关系已明确，是否保存摆放、尺寸与缩放仍待讨论。
- **识别模型复用（Q12）**：发起者希望图片到语义标签的识别使用其他开源项目，并要求回看候选软件使用的模型。尚未确认首版检索对多人属性关联的承诺；需区分外部模型的输出能力与 Kinshoko 自己的检索含义。

## 第四轮已确认

- **多资料库（Q9）**：发起者以 Obsidian 的多库方式为参考，明确同一用户可以建立多个资料库，并对资料库进行合并、删除。“资料库”因此成为可独立管理的领域单位。各库的数据归属、合并方向、删除范围和恢复方式仍需明确。
- **持续同步的使用目标（Q10）**：按推荐，以各设备都能新增素材、修改整理信息并离线使用为 roadmap 目标。冲突处理、删除传播、后端与交付阶段未定。
- **检索结果的含义（Q12）**：按推荐，首版使用整图标签找到参考候选，不承诺多个属性属于图中的同一人物。自由描述、人物属性关联与区域识别仍需单独验证。
- **参考组复用（Q13）**：按推荐，保存成员关系及各视图的位置、大小、缩放，复用时恢复这些布局和显示状态。

Q9 原先涉及首个实用版本的备份保护范围。此次回答明确了多资料库模型；备份内置流程与具体交付阶段仍需在多库边界明确后落实，不据“不是覆盖”一词推定恢复或合并的操作方式。

## 第五轮已确认

- **资料库数据（Q14）**：发起者确认每个库应拥有图片 metadata；接受本地库的完整目录与整体迁移方向。资料库的正式定义扩展为参考图及其元数据。参考组的归属重新讨论，不能按先前提案归入某个库。
- **合并（Q15）**：接受生成新库 C、保留来源库 A、B 的推荐。完全相同的图片如何合并记录、metadata 冲突和参考关系迁移仍待明确。
- **移除与删除（Q16）**：接受从列表移除和删除资料库分为两个动作；移除保留文件，删除先进入可恢复状态，永久删除另作明确操作。
- **恢复（Q17）**：接受从备份恢复为独立资料库，之后可主动合并。
- **自动与人工整理（Q18）**：接受自动结果直接用于检索、人工决定优先，重新识别保留人工添加、修改与否决。
- **清晰展示与增强（Q19）**：接受以原图像素作为整图和局部参考的基准，支持 1:1 与缩放；补充要求在 roadmap 中预留图片超分辨率工作。
- **模型表达**：发起者要求规划存储及数据关系的层级图。见 [数据层级草案](data-hierarchy.md)，图中未确认的归属和引用行为保留为提案。

## 第六轮已确认

- **参考组归属（Q20）**：参考组独立保存，可以引用多个资料库中的参考图。
- **成员状态（Q21）**：每个参考组成员独立保存裁切、位置、尺寸和缩放，继续关联原图；在一个组中修改不影响其他组。
- **合并去重（Q22）**：合并后的 C 对完全相同的原图合并记录并汇合元数据，相似图和不同版本各自保留。

| 局部参考 | 原图关联的整图或局部视图；临时与保存两种使用方式；组内每次使用状态独立 | 来源变化与缺失 |
| 参考组 | 独立保存，可跨库引用；成员各自保存裁切与布局，并整体复用 | 打包、备份、来源缺失与引用迁移 |
| Eagle 兼容 | 导入后独立管理已确认 | 迁移字段、重复、失败与增量导入规则 |
| 本地与远端数据 | 本地完整目录为主；恢复为独立库；备份与持续同步进入 roadmap | 库与参考组的保护范围、历史、同步冲突与接入 |
| 清晰展示与超分 | 整图、局部以原图像素为基准；1:1 与缩放；超分进入 roadmap | 超分的模型、质量验证、资源消耗、派生版本与显示选择 |

## 当前未决

- 合并时相互矛盾的人工决定，以及同名标签或别名的冲突。
- 来源缺失时的行为，资料库迁移、合并或恢复后的引用迁移。
- 参考组打包方式，以及库与参考组的备份范围。
- Eagle 导入字段、失败和重复处理。
- 备份的交付阶段、频率与历史；同步的冲突、删除传播与接入方式。

已确认的数据关系见 [数据层级与存储关系](data-hierarchy.md)。
