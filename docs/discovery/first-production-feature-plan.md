# 首个正式功能的实现方案与依赖选型

2026-10-03（Asia/Shanghai）。对应 [核查竞品技术栈与首个功能的可复用依赖](https://github.com/Yukk1No/kinshoko/issues/12)。**这是待评审提案，未安装依赖、编写应用或执行运行验收。** 推荐范围及依赖经过文献与源码核查；兼容、画质、故障恢复和性能仍须实测。

领域输入是正在评审的 [领域文档 PR](https://github.com/Yukk1No/kinshoko/pull/2) 及其固定版本 [数据与存储提案](https://github.com/Yukk1No/kinshoko/blob/90bef426bf0899f0341c3f407574826aa0ad794c/docs/discovery/data-storage-model.md)。本文件不新增领域定义或 ADR，也不把存储格式当作已经冻结的协议。

## 建议先交付什么

**建立／打开一个资料库 → 导入本地静态图片 → 浏览缩略图并清晰查看原图 → 关闭后重开。**

这是首个正式功能，后续围绕它增加检索和绘画参考。用户可创建多个库并逐个打开；首步只有一个活动库，切库时结束或保存待完成任务。本设备登记位置，库内保存自己的身份和元数据。初始验收覆盖静态 JPEG／PNG／WebP；动画及其他输入逐文件报告暂未支持，来源文件保持完整。

基础检索、Eagle 迁入、局部钉图、参考组复用和本地备份恢复仍是首个长期使用版本的交付内容。其中**本地备份必须经过恢复验证**，这一步完成不表示已适合把唯一素材副本长期交给软件。公开／自制样本先验，覆盖不足再补画师的小批真实素材；无独显 Windows 是运行基线，GPU 用于加速。

## 竞品怎样影响选择

| 已核验实践 | 采用的思路 | 对本方案的影响 |
|---|---|---|
| Curator 使用 Tauri 2、原生 TS／Vite；可见缩略图可换成原图 | 缩略图与原图各司其职，限制可见范围的工作量 | 详情按需读原图；图库 DOM 虚拟化另用现成组件，懒加载不等于虚拟化 |
| Hydrus 对方向、ICC 到 sRGB、缩略图 DPR 分别处理 | 清晰度包含像素量、方向与颜色 | 原图与缩略图分别验色；高 DPI 缩略图不能只沿用固定 300px |
| Monbooru 每库 DB／原文件分离；Hydrus 保留人工纠错与删除决定 | 身份、整理结果和派生缓存分开 | SQLite 为库内权威数据；原文件字节保留，缓存可重建 |
| BeeRef 的板内图会重编码；Nephele 桌面 GUI 栈未公开 | 保存范围和公开证据范围必须逐项判断 | 参考组包以后携带原字节；Nephele 用作流程／模型对照，不猜其内部依赖 |

固定源码、对应许可及边界见 [竞品前端核查](../research/competitor-stack-and-ui.md)、[图片管线](../research/image-pipeline-reuse.md)、[SQLite 接入](../research/storage-dependency-reuse.md)；模型沿用 [既有调查](../research/tagger-model-comparison.md)。这里只借鉴实践，使用独立发布的依赖；竞品源码复制需要单独审查具体文件。

## 推荐的依赖基线

| 用途 | 建议 | 复用什么／为何选择 | 剩余条件 |
|---|---|---|---|
| 桌面与构建 | Tauri 2、Rust；React 19＋TS＋Vite 静态前端 | 复用 OS WebView2、原生窗口及官方构建；React 的选择依据是图库组件适配 | 锁定相容 SDK／CLI／JS API 与工具链；构建、离线部署、CPU／集显实测 |
| 图库网格 | `react-virtuoso 4.18.16` 的 VirtuosoGrid | 等尺寸卡片、自适应列数、尺寸监听与滚动虚拟化，减少测量／布局自研 | 选择、焦点、改宽和快切库需测试；复杂瀑布流以后再评估 |
| 持久化与迁移 | `rusqlite 0.40.2`（bundled、backup）＋`rusqlite_migration 2.6.0` | 复用 SQLite 事务、备份 API 与迁移；Rust 领域入口统一控制写入 | 组合要求 Rust≥1.95；Windows 编译、迁移和中断恢复未验证 |
| 原图显示 | Tauri asset 协议＋WebView2 `<img>` | 直接显示保存的原文件，避免全图 base64／JSON IPC | scope／CSP、EXIF、ICC、混合 DPI 和实际内存成本须验证 |
| 缩略图 | 条件候选 `image 0.25.10` | 复用解码、方向与缩放，只开必要格式；不编写编解码器 | **ICC、非 sRGB 与 alpha 门槛通过后才采纳**；失败转评估 libvips 的 Windows 适配 |
| 身份与校验 | `uuid 1.26.1` 的 v4；`sha2 0.11.0` | 复用 ID 生成和完整 SHA-256；内容哈希与图片记录身份分开 | 同库判重还核对字节；跨库各自保存整理结果 |
| 前后端数据契约 | serde＋`ts-rs 12.0.0` | 从 Rust 返回类型生成 TS 声明，避免手写两套字段 | 生成物差异进 CI；检查 serde 表示、错误枚举及大整数的实际序列化 |
| 选文件与验证工具 | Tauri 官方 dialog；Rust 测试、Vitest、Tauri 官方 WebDriver 路线 | 复用原生文件选择和测试工具 | 实包端到端与画师操作仍需执行；mock 不证明原生行为 |

前三份研究笔记记录包版本、维护／许可证据与替代方案。补充工具已查一手发布信息： [uuid 1.26.1](https://crates.io/api/v1/crates/uuid/1.26.1)、[sha2 0.11.0](https://crates.io/api/v1/crates/sha2/0.11.0)、[ts-rs 12.0.0](https://crates.io/api/v1/crates/ts-rs/12.0.0)。uuid／sha2 为 MIT 或 Apache-2.0，ts-rs 为 MIT；[类型生成与 serde 支持](https://github.com/Aleph-Alpha/ts-rs)、[文件选择](https://v2.tauri.app/plugin/dialog/)、[测试入口](https://v2.tauri.app/develop/tests/)、[Vitest](https://vitest.dev/guide/)。

版本是核验基线，不是已构建通过的锁文件。实施时先核对 Rust MSRV、Node engines／peer、架构与原生链接，再提交 Cargo.lock 和前端锁文件；记录 WebView2 Runtime。标准库、Tauri 现有 runtime 和上述库足够承担第一步的任务与存取，额外池、状态框架、画布框架按实际需求再评估。

## 正式代码承担的职责

初始保留两个 Rust 模块，UI 通过小的领域接口使用它们：

```text
React 交互
  → Tauri 命令／生成的返回类型
    → Library Module：库身份、导入状态、元数据、查询与重开
      → rusqlite／迁移
      → Image Module：格式检查、方向、缩略图与有界解码任务
        → image（或颜色门槛后确定的现成库）
原图查看：Library Module 核对图片身份 → 受限 asset URL → WebView2
```

Library Module 初始提供创建／打开／关闭、导入、分页列图及取查看信息。调用者使用 `library_id + image_id`；URL 只定位本设备文件。ID／哈希通过字符串传输；大整数表示明确约定并校验，不用 TS 类型生成替代真实 JSON 检查。

Library Module 把文件复制／解码交给有界后台任务，DB 由专用线程顺序执行短命令；长文件处理不占用 DB 事务或 Tauri 主线程。导入有取消和逐项结果，成功以库内提交为准；切库时丢弃旧请求的 UI 结果并结束或保留任务。前端接收元数据、进度和资源入口，领域写入集中在 Rust；不创建逐包透传的通用仓储或假想存储接口。

自研集中于库身份、原字节保护、导入恢复、来源与人工整理规则、参考组独立成员等应用职责。编解码、缩放、数据库、迁移、虚拟列表、窗口控制和推理执行交给现成实现；只有证据指出具体缺口时才补局部代码。

## 原文件和写入

沿用每库一个 SQLite 保存库身份／版本／元数据、普通原文件及可重建缓存的候选。具体目录和公开 schema 留给格式验收；`library.json` 不作为第二份权威数据。库可移动，原文件位置相对库根，改路径不换逻辑身份。

导入采用同库暂存、完整校验、最小 pending 记录、拒绝覆盖地发布原文件、事务提交图片／来源并结束 pending。去重候选逐字节核对。重开按 pending 对账继续或报错；未知孤立文件先报告，成功项重试沿用记录，坏图／来源变化／空间不足逐项说明。**SQLite 事务与文件发布是两个操作**，恢复步骤与故障点见 [存储笔记](../research/storage-dependency-reuse.md)。

原图不重编码。缩略图的目标像素按卡片尺寸×DPR 分档，键含内容哈希、目标像素和管线版本。首先验证完整原图的颜色，再验缩略图颜色／alpha／方向；无法确认颜色时明确报错，决定用现成替代管线后才承诺支持。缓存丢失可重建，不能充当原文件或备份。

## 编码前的实验与正式代码质量

| 需要结论的问题 | 有限实验／证据 | 结论尚未取得时 |
|---|---|---|
| 所选版本能在 Windows 组合运行吗 | 最小依赖构建与 release 包；无开发工具环境离线安装；记录 MSRV、Node、Runtime、DLL | 保留候选，修正具体版本或链接方式 |
| 画师看到的颜色／方向／像素正确吗 | EXIF 1–8、ICC／CMYK／灰阶、透明边缘、小图细线；原图和缩略图分别对照；混合 DPI 物理像素 1:1 | 缩略图依赖未定；验证 libvips 等现成方案，不能自行补色彩转换算法 |
| 现成网格是否满足第一步规模 | 分规模构造列表、滚动／改宽／切库；记录 DOM 数、首次清晰时间、Core＋WebView2 内存和释放 | 调整加载／缓存预算；必要时比较 TanStack 的适配成本 |
| 文件与 DB 中断后能否保全 | 暂存、pending、发布、DB 提交各点终止；重开核对字节、元数据、记录数与失败清单 | 修正恢复顺序后再写入真实资料库 |

实验独立保留于 `research/` 或 `prototype/` 分支并记录复现入口；迁入正式工程的是结论、样本和经逐块评审的合格代码。实验的临时 DB／状态不成为用户库。采纳基线后，正式代码从最小功能开始，必要错误处理、稳定接口和关键行为测试同时实现。

每个实现 PR 要附一条可复现行为与对应规格；CI 做 Rust 格式／Clippy／测试、TS 类型检查、生成契约差异、前端测试／构建和 Windows 原生构建。关键测试验证原字节、重复／中断导入、重开和缓存重建；不测试第三方算法的内部实现。原生冒烟通过官方 [WebDriver](https://v2.tauri.app/develop/tests/webdriver/) 路线验证创建／导入／重开，颜色和绘画软件交互由实际设备验证；Tauri mock 不执行原生 WebView，不能据其通过宣称画质／DPI 通过。

具体预算与“找到可用参考”的阈值仍由 [验收样本与指标](https://github.com/Yukk1No/kinshoko/issues/4) 确认。构造列表只验证列表工作量，不证明真实图库、自动标签准确度或全部原图导入性能。

## 后续功能怎样接入

| 后续目标 | 延续的职责与现成方案 | 必须另验的内容 |
|---|---|---|
| Eagle 迁入 | 只读 Eagle 字段→现有导入入口；保留外部身份、原始 JSON、完整分类与来源 | 重导保护人工整理、多 item 同原图、区域坐标与部分失败 |
| 标签检索／自动建议 | PixAI v0.9 优先、WD SwinV2 v3 基线；复用 ONNX 执行候选；结果保存模型／来源／分数 | CPU 与 GPU、真实查询效用、运行时 Rust 接入／分发方式；不先把整套模型放入第一功能 |
| 参考组／桌面钉图 | 独立成员引用库和图片、转正后裁切；Tauri 窗口与全局退出能力 | 每次使用独立状态、画笔穿透、退出和 DPI；画布依赖届时按操作评估 |
| 本地备份恢复 | SQLite Online Backup＋协调原文件／独立组的完整快照 | 依赖闭包、恢复身份映射、原字节／元数据／布局和失败报告；首个长期使用版本必须通过 |
| 远端／同步／超分 | 稳定身份与相对定位延续；依赖选择在对应规格中确定 | 同步冲突及离线协议，增强结果身份；不把复制运行中 DB 当持续同步 |

这份提案交给 PR 评审；候选经过必要实验、画师验收后，由 [正式技术路线决策](https://github.com/Yukk1No/kinshoko/issues/9) 汇总，再进入 `/to-spec → /to-tickets → /implement`。当前没有关闭任何用户体验或数据恢复验证。
