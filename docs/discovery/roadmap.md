# Roadmap 方向

2026-10-01。本文记录已确认的能力方向；不是已排期的版本计划或实现规格。

| 方向 | 已确认的目标 | 尚未确定 |
|---|---|---|
| 本地绘画参考闭环 | Windows 单人使用；复用开源识别能力；自动标签参与检索，允许人工修正并保留人工决定；标签与中文别名组合查找整图候选；关联原图的整图或局部参考视图；Eagle 导入后独立管理 | 首个实用版本的完整范围、标签模型与验收指标 |
| 多资料库管理 | 每库保存图片及元数据，完整目录可迁移；合并生成新库并保留原库，完全相同的原图合并记录并汇合元数据；移除与可恢复删除分开；恢复产生独立库 | 元数据冲突、相关引用迁移与交付阶段 |
| 保存与复用参考组 | 独立文档，可引用多个库的图；成员各自保存裁切、位置、尺寸、缩放，保留来源关系并整体复用 | 来源缺失、引用迁移与打包 |
| 清晰展示 | 列表清晰预览；整图与局部参考以原图像素为基准；支持 1:1 查看与缩放 | 显示质量与响应体验的验收指标 |
| 图片超分辨率 | 明确预留超分能力的研发工作 | 模型与部署、线条与颜色保真度、伪细节、性能、派生版本、局部坐标映射与交付阶段 |
| 备份与恢复 | 设备损坏后仍可恢复辛苦收集的素材；恢复默认形成独立库；必须进入 roadmap | 库与参考组的保护范围、内置流程、目标存储、历史与交付阶段 |
| 持续多设备同步 | 持续传递新增与修改，包含各设备编辑与离线使用；必须进入 roadmap | 设备范围、组文档范围、删除传播、冲突、同步时机与接入方式 |

一次性换机恢复属于备份与恢复。持续同步维护各设备上的同一个逻辑资料库。

首版检索返回整图标签候选。人物属性归属、自由描述检索和区域识别另行验证。

发起者提出优先免费方案或开放存储接口的方向。当前还未决定把哪些责任交给 Kinshoko，哪些配置或存储资源由用户提供。

讨论中的建议是：由应用组织备份、恢复与同步流程，用户选择存储目标；通过可替换的接入方式使用本地目录或用户自有存储。该建议尚待确认，未选定具体工具或协议。

超分的数据关系建议是保留原图，把结果作为关联的派生版本。具体模型、元数据、显示选择与资源开销留在超分规格阶段，不在本轮选型。

资料库、元数据、参考组与存储位置的关系见 [数据层级与存储关系](data-hierarchy.md)。
