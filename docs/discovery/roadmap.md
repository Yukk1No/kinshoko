# Roadmap 方向

2026-10-01。本文记录已确认的能力方向；不是已排期的版本计划或实现规格。

| 方向 | 已确认的目标 | 尚未确定 |
|---|---|---|
| 本地绘画参考闭环 | Windows 单人使用；复用开源识别能力；自动标签参与检索，允许人工修正并保留人工决定；标签、文字与中文别名组合默认同时满足，查找整图候选；Eagle 导入后独立管理 | 首个实用版本的完整范围、标签模型与验收指标 |
| 多资料库管理 | 每库保存图片及元数据，完整目录可迁移；合并生成新库并保留原库，完全相同原图合并记录；向导先展示人工决定冲突，跳过时保留添加标签用于查找；移除与可恢复删除分开；恢复产生独立库 | 标签／别名映射、其他元数据冲突与交付阶段 |
| 保存与复用参考组 | 独立文档，可引用多个库的图；成员各自保存裁切与布局；普通组保存引用，另提供带原图的包；合并后经确认重连现有组并保存重连前备份 | 来源缺失、独立恢复后的连接、包的元数据范围与格式 |
| 清晰展示与桌面使用 | 列表清晰预览；整图与局部参考以原图像素为基准；支持 1:1 与缩放；桌面局部边界固定；钉图置顶，锁定阻止移动、调整尺寸与显示缩放，穿透独立且可退出 | 显示质量、响应体验与穿透退出的原型验证 |
| 图片超分辨率 | 明确预留超分能力的研发工作 | 模型与部署、线条与颜色保真度、伪细节、性能、派生版本、局部坐标映射与交付阶段 |
| 备份与恢复 | 设备损坏后仍可恢复素材；向导按资料库默认纳入关联参考内容，应用发现组与依赖；恢复默认形成独立库；必须进入 roadmap | 跨库依赖范围、恢复连接、目标存储、历史与交付阶段 |
| 高级检索与辅助候选 | 基础功能之后逐步探索文字语法、正则等模式匹配、LLM 辅助表达条件与 JEV 提供候选 | 语法与适用字段、检索含义、模型能力、准确度、部署、性能与交付阶段 |
| 持续多设备同步 | 持续传递新增与修改，包含各设备编辑与离线使用；必须进入 roadmap | 设备范围、组文档范围、删除传播、冲突、同步时机与接入方式 |

一次性换机恢复属于备份与恢复。持续同步维护各设备上的同一个逻辑资料库。

基础检索先落实标签、文字和中文别名的同一组条件：多个条件默认同时满足，任一条件与排除由用户明确表达，返回整图候选。人物属性归属、自由描述检索和区域识别另行验证。

建议后续依次探索更丰富的文字条件语法与模式匹配、模型辅助表达或检索候选。正则适用哪些字段、所谓“语法糖”如何表达，需另定规格；LLM 与 JEV 是候选方向，未承诺具体模型能力或选定接入方式。建议让用户能看懂并修正辅助条件，保留人工标签决定。

发起者提出优先免费方案或开放存储接口的方向。当前还未决定把哪些责任交给 Kinshoko，哪些配置或存储资源由用户提供。

备份由向导组织资料库及其关联参考内容，用户不用单独理解组文件的保护颗粒度；跨库引用应说明额外范围，完整补入外库还是只带依赖图片仍待确认。是否在首个实用版本交付内置备份，尚未明确。

存储接入的建议仍是用户选择目标，通过可替换接口使用本地目录或用户自有存储。该建议尚待确认，未选定具体工具或协议；同步流程的具体规格也未确定。

超分的数据关系建议是保留原图，把结果作为关联的派生版本。具体模型、元数据、显示选择与资源开销留在超分规格阶段，不在本轮选型。

资料库、元数据、参考组与存储位置的关系见 [数据层级与存储关系](data-hierarchy.md)。依据调查形成的身份、导入、合并与存储建议见 [数据与存储模型提案](data-storage-model.md)，尚未冻结格式或同步协议。
