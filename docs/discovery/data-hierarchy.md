# 数据层级与存储关系

2026-10-01。原图与元数据归库、参考组独立、成员状态独立及带原图的包已确认；下面进一步细化库内字典和来源关系，并给出存放建议。身份与操作规则见 [数据与存储模型提案](data-storage-model.md)，新细节仍属提案。

## 归属与引用

实线表示归属，虚线表示引用。对象不要求各有一张表或一个目录。

```mermaid
flowchart TB
    L["资料库（可多个）"] --> I["参考图记录"]
    L --> T["标签、别名与分类"]
    L --> S["导入来源与映射"]
    I --> O["原文件"]
    I --> M["图片元数据与人工决定"]
    M -. 标签引用 .-> T
    S -. 来源项映射 .-> I
    G["独立参考组文档"] --> V["成员：来源引用、裁切与布局"]
    V -. 库与图片身份 .-> I
    P["参考组包"] --> D["组文档快照与依赖原文件"]
```

- 每个资料库拥有自己的图片及元数据，完整本地目录可整体迁移。
- 标签字典、别名、分类与导入映射属于库；相同原图在不同库中可以有不同整理结果。
- 普通参考组保存引用，可跨库取图；同图的多次使用分别保存成员状态。
- 需要脱离原库使用时生成带原图的参考组包。

## 建议的存放职责

```text
资料库目录
├─ 一个权威 SQLite：库身份、格式版本、图片元数据、字典与映射
├─ 原文件：相对库根目录存放
├─ 需保留的派生结果：超分的规划位置
└─ 可重建缓存：缩略图、检索索引与显示缓存

独立参考组目录
└─ 带版本的组文档（建议 JSON）
   ├─ 成员来源、原图裁切与成员框
   ├─ 各成员内容的缩放与平移
   └─ 组画布视口

导出的参考组包
├─ 组文档快照与依赖清单
└─ 依赖的原文件
```

库身份由库内 SQLite 保存；设备配置登记库／组的位置及桌面窗口状态。提案建议用稳定库／图片 ID 引用记录，用原文件哈希校验内容，搬目录不改变身份。

## 合并、撤销与保护范围

- **已确认**：A、B 合并生成 C，保留 A、B；完全相同原图在 C 中合并记录并汇合元数据，相似图与不同版本保留。
- **已确认**：移除保留文件，删除先可恢复；备份恢复形成独立库；备份、持续同步及超分进入 roadmap。
- **建议**：撤销删除沿用身份，独立恢复生成新库身份；需要重连参考组时默认生成组副本，保留原组。
- **建议**：原文件与必要映射完整后，C 可以带明确的整理冲突清单可用；冲突标签的筛选行为待确认。
- **建议**：库备份包括可恢复删除内容；独立组另外纳入保护，可脱离来源恢复时带齐原图依赖。

待定的是冲突行为、包的元数据范围、备份交付范围与格式验证。Eagle 重导、中断边界及检查场景见 [模型提案](data-storage-model.md)。
