2026-10-02。依据 [数据实践调查](../research/data-model-practices.md)，融合 `85577e0` 与 `c07cb7c` 的两份提案。已确认多库、库内元数据、独立参考组、成员状态、合并与恢复的目标，以及普通组引用与带原图的包。操作规则见下文：合并冲突保留查找曝光，桌面局部边界固定，备份按库纳入关联内容；本轮确认外库整库补选、包的整理信息快照、临时补足显示、独立恢复组及 Eagle 重导和部分失败处理。首个长期使用版本必须交付经过恢复验证的本地备份；具体格式和高级能力仍待验证。

评审记录：[GitHub Issue #1](https://github.com/Yukk1No/kinshoko/issues/1)。归属与存放图见 [数据层级](data-hierarchy.md)。

## 推荐基线与实践依据

**每库保管原文件，并用一个 SQLite 保存库身份及元数据；参考组独立保存为带格式版本的 JSON；索引与显示缓存可重建。**

| 调查依据 | 本提案的取舍 |
|---|---|
| Eagle 的素材可属于多个文件夹，API 与磁盘 JSON 有差异 | 分类是元数据关系；导入保留来源身份和原始字段，兼容不要求采用 Eagle 的原生存储格式。 |
| ImoutoRebirth 分开记录身份、来源、路径；Curator 同路径换内容会复用 ID | 分开图片身份、文件内容与存放位置，防止旧裁切指向另一张图。 |
| Hydrus 保留已删除的标签，Monbooru 按来源更新标签 | 分开导入／模型结果和人工决定；人工否决需要持久保存。 |
| BeeRef 成员可独立裁切，但嵌图会重新编码 | 保存每次使用的成员状态；参考组包携带未经重编码的原文件。 |
| 部分图库的导出、合并和恢复保留不同字段 | 明确元数据保护范围和引用映射，不能只以文件去重或备份名称判断完成。 |

证据与固定源码版本见 [Eagle](../research/eagle-storage-practices.md)、[图库](../research/library-storage-practices.md)、[参考板](../research/reference-board-practices.md) 和 [补充项目](../research/supplementary-data-practices.md)。本提案没有新增跨库公共图片池或全局标签数据库。

## 身份、内容与位置

| 信息 | 用途与变化规则 |
|---|---|
| `library_id` | 标识逻辑资料库；搬目录、改名、撤销可恢复删除及同步副本保留；合并新库、从备份恢复独立库生成新值。 |
| `image_id` | 库内参考图记录；改名、整理和搬库保留，对外引用同时带 `library_id`。不同库可对同一原图保存不同元数据。 |
| `content_sha256` 与字节数 | 完整原文件的内容校验与判重线索，不代替图片记录身份。 |
| 当前存放位置 | 本设备的库目录或存储后端中的文件位置；可以变化，不作为参考组的主要来源身份。相同原图可临时补足显示，不改变组的来源引用。 |
| `group_id / member_id` | 普通保存与确认后的合并重连保留组身份；复制为新组或从备份恢复独立组生成新 `group_id`，成员在组内唯一。同图重复使用也要有不同成员。 |

ID 建议使用不依赖路径的生成式标识，具体编码未冻结。原文件建议入库后不原地改写；不同字节成为另一条参考图记录。外部替换文件时报告校验失败，不沿用旧裁切静默展示新内容。

判重计算完整 SHA-256 和大小，最终合并核验相同候选的原文件字节。局部摘要、缩略图和感知相似度只用于找候选。[LocalBooru 的抽样导入路径](https://github.com/DonutsDelivery/LocalBooru/blob/79ad5ff0b634ace3f74d28651311381b03f8fc1e/api/services/importer.py#L434-L443) 是需要避免直接照搬的边界。

同库建议相同原文件只保管一份、重复导入汇合来源；跨库各自完整保存，以便独立迁移。来源未挂载或不可读只改变本设备的可用性，不删除图片记录，也不作为删除动作传播。

## 库内保存什么

下表表达需要保留的数据和关系，不要求每行对应一张表。

| 数据 | 最少保留的内容 |
|---|---|
| 库信息 | 库身份、名称、格式版本及可恢复删除状态；由库内 SQLite 保存。 |
| 图片记录 | 图片身份、原文件哈希／大小／相对位置、格式、尺寸与方向、原文件名、展示名称、来源 URL、备注和状态。 |
| 标签字典与组织 | 稳定的库内 `tag_id`、规范名称、别名与分类；改标签名不换 ID，别名先在当前库解析。Eagle 文件夹树、全部归属与标签组也归该库。 |
| 导入／模型标签 | 图片、标签、来源及当前结果；模型提供时保存原始分数、模型版本与识别参数。重跑只刷新对应模型的当前结果。 |
| 人工标签决定 | 图片与标签的明确添加或否决；撤销人工决定才回到来源结果。 |
| 导入追溯 | Kinshoko 登记的导入来源、外部 item ID 与文件哈希的绑定，原始库级／单项 JSON、字段映射版本与异常。 |
| 图上标注 | 图片本身的区域备注、坐标基准与来源；参考组成员的裁切另归成员。 |
| 合并／恢复映射与冲突 | 旧库／记录到新库／记录的关系，标签和分类映射，双方元数据出处及未解决冲突。 |

标签和分类是逻辑组织，不决定原文件路径。Eagle 没有可直接依赖的跨库稳定身份保证，导入来源由 Kinshoko 登记，路径只帮助定位。未知字段保留原始值，并报告尚未支持其行为；日常整理结果由 Kinshoko 的记录负责。

有效标签按已确认的规则计算；计算结果可以重建，来源结果与人工决定必须备份：

```text
未解决的合并人工决定冲突 → 保留添加用于查找，标记冲突，保存双方
没有冲突且人工添加 → 参与筛选
没有冲突且人工否决 → 不参与筛选
没有人工决定 → 已导入标签 ∪ 当前生效的模型标签
```

同一张图把“蓝发”改成“紫发”，需要保存对前者的否决和对后者的添加。模型结果按来源更新，不承诺保留无限次预测历史。合并前各库的相反决定先分别保留，不能直接套用“否决优先”消掉另一方的人工添加。

合并向导先展示相反的人工决定，用户可以解决或跳过；跳过后保留冲突标记和查找曝光。A 添加“蓝发”、B 否决“蓝发”时，暂未解决的 C 仍可被“蓝发”找到；否决不是另一个标签。双方分别添加“蓝发”和“紫发”时，两者都用于查找，不能仅凭不同颜色标签就认定整图不可能同时具有它们。

不同备注、来源和分类归属保留出处。同名标签默认对应，合并向导允许纠正；标签含义不兼容时不能强行合一。相同别名指向不同标签时保留两种含义，用户明确选择查找条件，不静默把两个标签合成一个。名称规范化、候选匹配与纠正方式留给合并规格。用户解决冲突后按新决定重新计算有效标签。排除条件按这个有效标签集合判断，不把冲突解释为同一标签同时被包含和排除。

基础检索沿用点击标签、文字输入和中文别名表达同一组条件，多条件默认同时满足；“任一条件”与排除由用户明确表达，结果仍是整图候选。文字语法、正则等模式匹配、LLM 辅助表达条件与 JEV 等模型提供候选按 [roadmap](roadmap.md) 逐步验证，不改变人工整理数据的归属。

## 参考组：成员状态与坐标

普通参考组保存格式版本、`group_id`、名称、成员列表与组画布视口。成员保存自己的身份、来源 `(library_id, image_id)` 和预期原文件哈希。跨库引用在加载时解析，SQLite 外键不能保证另一个库当前可用。

局部范围在钉图前选定，桌面钉图不修改边界。移动窗体和调整显示比例只影响已选区域的展示；重新选择区域属于参考内容编辑流程。

据此简化坐标建议，显示字段仍需原型验证：

| 层级 | 建议保存 |
|---|---|
| 来源基准与裁切 | 成员记录完成方向校正后的来源宽高与原图像素裁切 `crop`；整图使用明确的整图标记。来源宽高用于校验坐标。 |
| 成员 | 组画布位置 `x/y` 与显示比例 `scale`；显示尺寸由选区基准和比例计算，暂不为桌面局部新增可越出选区的平移状态。 |
| 组画布 | 整组的平移与缩放视口；不与某个成员的内容缩放混用。 |

位置、显示尺寸与缩放需能恢复，但不要求每个描述都对应独立字段。屏幕 DPI、桌面窗口位置和显示器选择属于设备配置；字段归一化及 1:1 显示通过参考显示原型核验。

同图在同组裁左眼、右眼，是两个成员；复制到另一组后分别保存状态。参考视图直接作为成员中的显示数据，无须跨组共享可变裁切对象。单独保存一个视图可使用单成员参考组。

桌面钉图置于绘画软件上层；锁定阻止移动、调整尺寸与显示缩放，鼠标穿透独立选择，并必须有可靠退出方式。这些使用状态与原图、标签及裁切边界分开，持久化位置由桌面交互规格确定。

加载时校验格式版本、组内成员 ID 唯一、坐标范围和数值合法；遇到未知版本、基准不符或来源哈希变化，保留文档并报告异常。Eagle 区域评论的原始坐标先保留，样本验证后才转换；超分显示也继续映射到原图基准。

普通组只保存引用已获确认。来源库离线或原文件缺失时，其他库中完全相同的原图可以临时补足显示，组的来源引用与元数据归属不变；文件身份必须核验，不依靠文件名或缩略图猜测。完全找不到原图时保留成员、裁切和布局，说明缺失；永久改连到另一库需用户确认，缓存预览不能冒充原图已恢复。库内图片删除与既有组的关系仍需单独明确。

参考组包默认包含组文档、依赖清单、未经重编码的原文件，以及所用图片的标签、备注与来源快照；同一原文件只携带一次，不携带来源库的其他素材或完整操作历史。包内成员到文件的映射允许脱离原库打开，来源身份继续保留。整理信息表示导出时的快照，不反向更新来源库；包内快照另存为新组时生成新组身份，包不自动恢复整个来源库。具体序列化与来源字段的完整保留需通过往返验证。

## 本地落盘与写入

建议由 **一个库内 SQLite 同时保存库身份和整理数据**，不再设置独立可修改的 `library.json`。数据库与可读导出有明确主从关系，避免日常写入两份权威数据。文件名仅为职责示意，尚未冻结公开格式。

```text
<用户选择的库目录>/
  library.sqlite          # 库身份、格式版本、元数据、来源与引用映射
  originals/ab/<hash>.png  # 原文件；位置相对库根目录
  derived/                # 预留需保留的超分结果，格式另定
  .cache/                 # 缩略图、检索索引与渲染缓存

<用户选择的参考组目录>/
  眼睛参考.json           # 带版本的组与成员；改文件名不改变组身份

<本设备应用配置>/
  库与组的位置登记、窗口状态和偏好
```

SQLite 提供库内关系的事务更新与查询；代价是需要显式格式迁移、数据库读取工具及可读导出。原文件副本增加磁盘占用，但保持库独立与原文件字节。应用配置可以重建位置登记，不拥有唯一的图片元数据或组布局。[SQLite 应用文件格式](https://www.sqlite.org/appfileformat.html)

建议导入顺序：只读来源 → 复制到暂存文件并完成校验 → 发布原文件 → 事务提交图片、来源与整理信息。SQLite 事务不覆盖文件系统；失败后不得报告导入成功，已落盘而未提交的文件留待检查／重试处理，不能因此删除来源文件。

组保存建议先写出并校验新文档，再替换旧版本；中断后应能取回上一次完整保存。文件发布、替换与数据库迁移都需要中断测试，不能仅凭顺序推定崩溃安全。

## Eagle 导入与库的变更

| 操作 | 建议规则 |
|---|---|
| 首次导入 Eagle | 原图、标签、完整文件夹层级与所有归属、来源链接及整图备注为实用版导入验收内容。区域评论保留原始信息，坐标核验后恢复显示；记录来源与外部 item 身份，逐项报告未支持及失败。 |
| 重导同一来源 | 新增素材并刷新 Eagle 提供的信息，保留本库人工整理；Eagle 删除图片不自动删除已迁入副本，原文件内容变化保留新旧版本。来源移库后的辨认规则还需验证。 |
| 一批导入部分失败 | 保留成功项，整体报告部分成功，列出失败原因并允许重试；重试不重复创建已成功的图片记录。 |
| 多个 Eagle item 含相同原文件 | 汇入一条图片记录，保留全部外部 ID、备注和归属；不能只跳过重复文件就认为元数据已导入。 |
| 搬库、改名、从列表移除 | 搬库／改名保留身份并更新位置；移除只改设备登记。整体搬迁关闭写入并释放连接，或生成一致快照。 |
| 删除后撤销 | 库的可恢复删除保留完整数据；撤销沿用原库／图片身份。建议图片删除也保留原文件、人工决定与追溯；库删除不等于逐图删除。 |
| A、B 合并为 C | 新建 C 与图片记录，原文件精确去重，保留来源及冲突；输出旧图片／标签／分类到 C 的映射，保留 A、B。 |
| 从备份恢复独立库与组 | 资料库与恢复出的参考组是独立副本，组连接恢复出的库；不改写当前组。建议生成新库／组身份、保留库内图片 ID 并输出映射，与撤销删除区分。 |
| 持续同步同一库 | 保留逻辑库与记录身份，每个设备各有自己的位置；协议、删除传播及冲突规则另定。 |

**合并的完整性与整理冲突分开处理。** 建议 C 先在独立目标完成；缺原文件、记录或必要映射时保持可重试的未完成状态。结构与依赖检查通过后可以登记为可用新库；向导展示的人工决定冲突可以暂时跳过，后续仍明确标记，相关添加标签继续参与查找。

已有组不因合并自动改写。按已确认的 Q28，先预览受影响组，经用户确认后用映射和原文件哈希核验，重连现有组到 C 并保存重连前备份；普通组身份保持不变，用户继续使用同一个组。恢复出的组独立保存并连接恢复库；若要修复现有组，则先预览并经用户确认重连，同时保留原状态。直接复制库目录会保留库 ID，重新登记时需区分迁移／同步副本与新建独立库。

## 备份、远端与同步

备份以资料库为用户理解的单位，默认纳入所选库及围绕它产生的参考内容。向导引导选择所需内容，列出覆盖范围；应用自动发现关联参考组与原文件依赖，不要求用户分别理解和勾选组文件。独立保存的参考组仍保持跨库归属，备份是按引用关系纳入它们。

提案建议保护一致的 DB 快照、原文件、人工决定、导入字段、映射与冲突、组布局及需保留的派生结果，**包括可恢复删除的数据**；缓存可省略。所选库关联的组若还引用其他库，向导默认提示补选完整外库，在执行前列清追加范围与容量，由用户决定；代价是备份体积可能增加。缩减范围时不能继续宣称相关组已被完整保护；缺失内容需明确报告。默认备份范围、关联链继续扩展的边界，以及未关联所选库的组如何纳入，仍需明确。

建议取得库与组快照时协调写入，固定本次引用关系，保护所需文件不被清理，再复制并核验；缺失清单为空且校验成功才标记完整。SQLite Backup API 负责 DB 快照，外部文件与独立组的一致保护由应用组织。[SQLite 备份 API](https://www.sqlite.org/backup.html)

可读导出建议包含版本、原文件清单、来源、人工决定、别名与映射；由权威 DB 生成，迁出与恢复分别验收。参考组包携带一组参考及所用图片的整理信息快照，仍是导出方式，不成为普通备份向导必须暴露的独立选择。

远端接入分别支持原文件取回、备份保存与同步变更交换；引用不写死盘符、云商 URL 或凭据。先保证完整本地工作副本，远端按需取图的离线保留范围另定。用户自有免费存储可作为目标，具体服务未选定。

稳定 ID 与独立文档为同步提供基础，尚未解决离线编辑、删除及冲突。各设备活动 SQLite 留在本地，不以双向覆盖运行中的数据库文件实现持续同步；WAL 的同机约束与日志搬迁也需遵守。[SQLite WAL](https://www.sqlite.org/wal.html) 本地备份与恢复必须在首个长期使用版本交付并通过恢复验证；远端备份、持续同步的协议与交付阶段留在 [roadmap](roadmap.md)。

超分保留关联原图的新结果，不覆盖原图或重定义旧裁切。用户保存的增强结果需要保护，不能仅因可重新跑模型就当作缓存清理；结果身份、模型参数与质量在超分规格中确定。

## 待执行的检查场景

本轮融合的是模型与操作建议，尚未实现或运行真实资料库往返测试。

| 场景 | 需要核验的结果 |
|---|---|
| 同图左眼／右眼入组，复制到另一组，再钉到桌面移动与缩放 | 各组成员状态独立，桌面操作不改变局部边界，保存／加载恢复相同参考画面。 |
| 改盘符、库名，拔掉源盘，另一库保有同原图；再在同路径换另一张同大小图 | 移位可重连；同原图临时补足显示而不改写引用；内容变化不静默接管旧裁切。 |
| Eagle 一图多分类、局部评论，人工整理后重导，来源删图或换内容 | 原文件与完整组织关系保全；人工整理不丢；源删除不删副本，内容变化保留新旧版本；评论转换有样本依据。 |
| 1,000 项导入中 12 项失败，再次重试 | 988 个成功项保留，整体标注部分成功；失败原因可查，重试不重复创建成功记录。 |
| 导入在原文件发布后、DB 提交前中断；组替换保存时中断 | 重试不伪造成功、不删来源，旧完整组可取回。 |
| A/B 同原图的人工标签相反，向导中跳过冲突，再重连原组 | 向导先展示冲突，相关添加标签继续曝光；确认后重连现有组，身份不变且旧连接可恢复。 |
| 可恢复删除后撤销；在原库／组仍存在时从备份恢复独立库与组 | 前者沿用身份；后者独立恢复，组连接恢复库，当前组不被改写；可恢复内容与整理数据被保护。 |
| 跨库参考组打包到空白设备打开 | 原文件与画面完整，脱离来源库可用；所用图片的标签、备注与来源快照可回看，来源库其他素材不被带入。 |
| 向导选择资料库，提示补选外库，备份并恢复跨库参考组 | 执行前范围与容量可查；确认后外库完整纳入，恢复组连接恢复库；缺失内容不被标记完整。 |
| 锁定钉图，开启鼠标穿透，再退出 | 锁定阻止移动、调整尺寸与显示缩放，穿透独立且可可靠退出，局部边界保持不变。 |
| 清理缩略图、全文／向量索引缓存 | 原文件、人工决定、来源与组状态仍完整，索引可重建。 |

领域边界仍需明确：新素材的收集入口、静态与动态参考的首阶段范围、库内图片删除对既有组的影响，以及备份默认范围与关联链扩展。名称规范化、Eagle 来源移库辨认、具体格式与中断／往返流程属于规格和验证工作。桌面显示与穿透退出需要原型验证，远端、同步、超分和高级检索按 roadmap 逐步制定规格。
