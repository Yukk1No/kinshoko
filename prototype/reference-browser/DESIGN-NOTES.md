# 设计说明

2026-10-05。这版样稿从整个仓库出发，而不是只从界面简报出发：[领域对齐记录](../../docs/discovery/alignment.md)（到第十三轮）、两份 ADR、[验收约定](../../docs/validation/acceptance.md)、[#7 钉图原型](https://github.com/Yukk1No/kinshoko/pull/21)的试用结论、[logo kit v1.1](../../design/logo-kit/README.md) 和验收样本清单。下表每一行写明界面上的做法和它的依据。

## 一种结构，不再三选一

#14、#15 各给了 A／B／C 三种结构，请画师挑选。这里只给一种，原因有三：

1. 第十二轮确认钉图来自截图逻辑，参考是桌面上的独立窗口。#15 在网页里另做“本次参考区”，B、C 两种方案主要在比较这个区域该放在哪里，这个前提已经不成立。
2. 验收约定说画师的找法是“筛选后浏览，看到合适的再选取”，并且首版不对找参考的耗时做定量验收。所以该比较的是同一条流程里每一步顺不顺，而不是三种布局哪个更快。
3. 三套方案共用一份代码，每个改动都要改三遍，评审时也很难看出哪些问题是结构本身带来的。

结构是：图标轨 → 上下文侧栏（文件夹／参考组／截图历史）→ 查找框与标签分组 → 瀑布流；查看原图时覆盖侧栏与图片墙；钉图浮在最上层，不属于任何面板。

## 依据与做法

| 依据 | 界面上的做法 |
|---|---|
| 代表场景：点分类好的标签或输入文字找图（第一轮） | 查找框与“标签分组”条并列。分组（发色、发型、刘海、发长、画面、作品）只影响显示，不影响查找（GLOSSARY：标签分组）。分组里的数字是当前结果中的张数，加条件前就知道会不会变成 0 张 |
| 多条件默认同时满足，任一与排除由用户明确表达（Q29） | 条件是查找框里的小块。点击＝同时满足；Ctrl＋点击或 Alt＋Enter＝与上一个条件“或”；右键或点小块前的圆点＝排除（虚线、删除线） |
| 直接输入即匹配；同一个词命中多个命名空间时在下拉中点选，不选则都匹配（Q95、Q96） | 下拉第一行固定是“查找‘某某’”，回车走这一行，按名称、别名、备注和来源链接匹配全部；下面按命名空间列出候选与别名来源（“别名 青髪”）。歧义时提示“不选则下面几项都匹配” |
| 标签命名空间：作者、角色、作品、一般；命名空间是身份的一部分（Q90～Q92） | 候选与信息栏都标命名空间。`作者:某某` 与 `角色:某某` 在测试里是两个标签 |
| 作者来自来源与人工，信息栏顶部单独显示，点名字看全部图（Q93、Q94） | 作者名来自 pixiv 作品接口；信息栏第一行是作者与来源链接；点名字以 `作者:某某` 为条件重新查找 |
| 自动结果参与检索，人工决定优先，否决会持久保存（Q18） | 信息栏的每个标签标出出处：来源（pixiv）、自动（虚线，带分数，有 #6 结果时）、人工（金色星标，取自 logo 的星）。否决后标签移到“已否决”，不参与查找，可撤销 |

| 智能文件夹进入 roadmap（Q84～Q89） | 侧栏只占一行“智能文件夹 · 规划中”，不做功能 |
| 可恢复删除的图退出普通检索，已有组仍可用（Q42） | Delete 移到回收站，可撤销；回收站在侧栏底部，图在那里可恢复；参考组仍能显示它 |
| 内容分级与全局安全模式：默认开启，有快捷键；第十四轮起图片墙与查找中隐藏，参考组与钉图原位模糊（验收约定、Q97～Q111） | 图标轨底部的封印书，Ctrl+Shift+S；做法见下文“封印书”一节。信息栏可人工改分级，并能“恢复来源分级” |
| 框在 Kinshoko 显示的参考图上得到参考视图，按原图像素裁切（Q69）；1:1 不再是要求，但以原图像素为基准（Q68） | 查看时 F1（或 Shift＋拖动）框选，选框旁实时显示“394 × 394 px（原图像素）”。“原图像素”按钮按 1 原图像素对 1 屏幕像素显示；放大到 200% 以上改用像素化插值，便于看清线条 |
| 截图与库内局部同一手势；剪贴板图片按截图对待（Q68、Q69） | 网页不能截屏：F3 或 Ctrl+V 把剪贴板图片作为截图钉住，进入截图历史。查看器外按 F1 会说明正式版的截图行为 |
| 截图历史保留最近若干张，未收藏也未钉住的旧截图被丢弃（GLOSSARY） | 截图历史保留 10 张，按这条规则滚动丢弃；可钉住、收藏到某个资料库的某个文件夹 |
| 参考组只引用资料库中的参考图；保存时列出未收藏的截图，选择资料库后一并收藏（Q70、ADR-0002） | “存为参考组”对话框列出未收藏的截图，每张选一个资料库或“不收藏，不进组”。组卡片显示涉及的资料库（如“角色参考 + 画法练习”） |
| 翻转、旋转随组保存；透明度、锁定属于桌面状态（Q71） | 保存的成员只含局部、位置、大小、翻转、旋转；对话框写明透明度和锁定不随组保存。重开后桌面状态回到默认 |

| 贴边隐藏：全部钉图收到最近的屏幕边，留细边，交还焦点；再按一次回原位（Q68） | F4。每张钉图滑到离它最近的边，只留 6 px；指针碰到细边时那一张滑出。焦点交给“模拟画布”，所以 F4 之后可以直接下笔 |
| 缺失原图时保留成员与布局并明确提示（Q33、Q42） | 引用找不到时，钉图与组缩略图显示“原图缺失”，成员、裁切、布局不变 |
| 收集入口包含拖放（Q40） | 把图片拖进窗口即收藏到当前资料库与当前文件夹，只在本次运行中保存 |
| 默认关闭、只写本地的使用日志（验收约定·反馈渠道） | 设置里开启。记录查找条件、打开／钉住／存组等事件；图片以样本 SHA-256 前缀记录，不含文件名与图片；画师手动导出 JSON |
| 免安装交给画师运行（验收约定·开发原则） | 单文件 `index.html`（JS／CSS 内联，file:// 可直接打开）加 `media/` 目录，`npm run pack` 打成 zip。#14、#15 需要 pnpm 和开发服务器 |
| 样本用验收清单，覆盖发色、发型、刘海、线稿、厚涂、多人、极长图、透明图（验收约定） | 252 张 pixiv 样本按清单校验后使用；pixiv 缺的透明、极长、极宽、细线、小图用 5 张自制图补齐，放在资料库「画法练习」的“显示测试” |
| 第二个资料库里有相同原图（Eagle 样本约定） | 「画法练习」与「角色参考」共享 28 张原图，各自是独立记录、独立整理。参考组可以同时引用两边 |

## 视觉

- **品牌色只放在框架上。** 日间：纸白 `#F7F3EA` 底、墨紫 `#2B2747` 文字、樱粉 `#E0768F` 表示选中与焦点；夜间：墨紫系底色、奶油 `#F4ECDC` 文字、金 `#E3B34F` 表示选中与焦点，与 logo kit 的日夜配色一致。人工决定统一用金色星标，取自 logo 的星。图标轨顶部是 32 px 像素对齐的书签标。
- **图片底色保持中性。** 图片墙用接近中性的灰（日间 `#EAE9E6`，夜间 `#161618`），查看器提供深灰、中灰、浅灰、棋盘四种底色。画师要靠眼睛判断参考图的颜色，偏色的底会干扰判断。
- **缩略图不加装饰。** 默认不显示图名，悬停只有一圈描边；图片像素没有位移、缩放或透明度动画。动效只用在图标轨的指示条跟随、图标悬停上浮 1 px、提示淡入、侧栏和弹出层的进入，以及钉图贴边。系统设置为减少动画或在设置里勾选时，所有过渡都关闭。
- **字体用系统字体栈**（Segoe UI Variable、Microsoft YaHei UI），不下载字体。

## 工程取舍

- **瀑布流几何是纯函数**（`src/layout.ts`）。图片尺寸来自资料库记录，不从 DOM 测量；同样的输入总是得到同样的列，“回到同一张图”因此是精确的。可见范围按列二分查找，只挂载视口上下 700 px 内的卡片。没有采用 #14 的 TanStack lanes：尺寸已知时，它的测量与锚点修正反而更复杂。
- **锚点记图片，不记像素。** 滚动时记下视口左上最近的那张图和它的偏移；改宽、改密度、开关侧栏后按这张图恢复。新查找从顶部开始。查看器盖在图片墙上，图片墙保持挂载，所以返回时滚动位置本来就没变，只需把焦点还给刚看的那张图。
- **检索语义有单元测试**（`src/logic.test.ts`）：默认同时满足、任一、排除、别名、歧义词匹配全部、人工决定优先、回收站退出检索，以及瀑布流的比例、限高、可见范围和改宽后的锚点。
- **file:// 下不能读取图片像素**，所以局部预览全部用 CSS 裁切，不用 canvas。

## 封印书（#27）

2026-10-06。按第十四轮 Q97～Q111 与选定的封印书设计（[`design/seal-book-concepts/round5-a1-round-lock`](../../design/seal-book-concepts/README.md)）改写安全模式。

| 依据 | 做法 |
|---|---|
| 图片墙与查找中隐藏，其余图片补位（Q97） | 开启时 questionable 与 explicit 不进入查找索引：结果、文件夹计数、标签分组计数、查找候选、资料库菜单里的张数都只算可见的图，也不提示“另有 N 张”（Q101）。图片墙右键菜单不再有“显示这张” |
| 查看中开启（Q103） | 正在查看的图被封印时，查看器回到图片墙；上一张、下一张本来就只在可见结果里走 |
| 参考组与钉图原位模糊、单张确认（Q98）；解除时轻量碎裂或消散，不飞行（Q107） | 钉图上盖模糊层和一把小号圆锁（与封印书同一把锁）。解除时锁梁弹开、锁缩小消失，模糊层原地淡出约 0.4 秒 |
| 控件（Q100、Q108） | `src/sealbook.ts` 移植第五轮 A1 的 24 px 母版；按进度值绘制，动画中途再点会从当前画面掉头。日间锁用深樱粉 `#C85672`，夜间用金 |
| 封印：约 0.3 秒内无法辨认，整段约 1 秒（Q104、Q109） | 屏幕上的成人图以“替身”在固定层里演出：0–240 ms 模糊到 14 px 并盖上 92% 墨色；260 ms 起逐张（间隔 30 ms）飞进封印书；其余图片在 280–900 ms 从当前位置连续滑到新位置（FLIP） |
| 释放：英雄式演出，书打开，图飞回原位，补位连续（Q97、Q104） | 书打开时按钮处扩散一圈光；150 ms 起逐张（间隔 55 ms）从书里飞向各自的新位置，带一点回弹，飞行中逐渐清晰；落地那一刻真卡片才出现。其余图片 40–720 ms 连续让位。视口外的图不飞，直接就位 |
| 封印优先（Q111） | 释放中途开启时，每张替身从当前位置、当前模糊程度掉头，200 ms 内重新糊住再飞回书里；不受“可打断”设置影响 |
| 打断（Q105）与播放期间的输入（Q110，未决） | 设置“释放期间”三选一：完整播放、图片墙照常操作（候选 B，默认）；完整播放、播完前图片墙和侧栏不响应（候选 A）；可打断：在图片墙上一操作就直接播完 |
| 减少动画（Q106） | 系统设置或样稿设置开启时，没有替身、没有补位动画，开启立即消失、关闭直接出现 |

设置的“开发者检查”里可以把特效慢放 ×5，并在右下角显示上一次封印／释放的时长、飞行张数、帧率与最长一帧，用来逐帧核对 0.3 秒门槛和记录帧率。

### 运行记录（2026-10-06，开发机，无头 Chrome，1440×900，开发模式）

为了让成人图出现在第一屏，把最上面的两张临时改成“成人”测试；14 张 R-18 样本排在最后，在墙底另测了一遍。

- **直接开启**：100 ms 时替身模糊 11.4 px、墨色 78%；约 210 ms 达到 14 px、92%；约 1.0 秒全部收进书里。8 张其余卡片在补位中有连续的位移动画。
- **释放中途开启（Q111）**：释放 400 ms 时开启，替身原本还糊着，直接掉头，800 ms 内结束；释放 900 ms（替身已清晰）时开启，106 ms 时已模糊 12.5 px、墨色 82%。
- **释放**：4 张替身约 1.3 秒全部落地，落地后真卡片出现，没有残留的隐藏卡片；释放中再关闭／开启都从当前位置继续。
- **候选 A**：释放期间图片墙和侧栏不可操作，图标轨的封印书仍可点；播完后恢复。**可打断**：释放 300 ms 时点一下图片墙，替身全部就位、补位动画结束。**减少动画**：开启、关闭都没有替身和补位动画，计数立即更新。
- 钉图：开启时原位模糊并显示小圆锁；关闭时锁弹开、模糊淡出，不飞行。
- 构建出的 `dist/index.html` 用 file:// 打开，开关封印书后计数在 238 与 252 张之间切换。
- `npm test`（14 项）、`npm run build` 通过。

“无法辨认”这里用“模糊 ≥ 12 px 且墨色覆盖 ≥ 75%”近似，最终仍要用户看录屏判断。帧率只在开发机的无头浏览器里看过，没有在约 250 张图的真实窗口里录屏，也没有在画师电脑上运行。

## 请画师回答

按验收约定，这些是定性反馈，不设门槛：

1. 输入或点选几个条件后，“这一屏值得刷吗”？（值得／一般／不值得）
2. 标签分组和查找框，平时更常用哪一个？分组的划分（发色、发型、刘海、发长、画面、作品）合不合适？
3. 查看后按 Esc 回到图片墙，有没有找不到刚才位置的时候？
4. F1 框选、Enter 钉住，和 Snipaste 的手感差在哪里？
5. 钉图的右键菜单里，哪些操作应该放到外面一键可达？
6. 默认不显示图名、只看图，够不够用？图片大小滑杆常不常动？
7. 安全模式的模糊程度和“确认后显示”是否合适？
