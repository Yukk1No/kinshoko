# 桌面钉图原型（PROTOTYPE，#7）

一次性原型，回答 [#7](https://github.com/Yukk1No/kinshoko/issues/7)：画师在实际绘画时，能否清晰、顺手地使用钉图？代码不进入正式实现；结论写回 issue。

Tauri 2（WebView2）＋ 原生 JS。状态、截图历史和原型资料库都放在 `%APPDATA%\dev.kinshoko.prototype.desktoppin\`，文件名都带 `PROTOTYPE`，可以随时删除。

## 运行

```bash
npm install
npm run build       # 生成 src-tauri/target/release/kinshoko-desktop-pin-prototype.exe，免安装，可拷到画师电脑
npm run demo        # 开发模式
python scripts/probe_windows.py   # 开发机端到端检查（约 20 秒，会移动鼠标，并清空原型的状态和截图历史）
```

需要 Rust（MSVC）、Node 22 和 WebView2 运行时（Windows 11 自带）；检查脚本需要 Pillow。

## 第二轮：按试用反馈改为“截图钉图”（2026-10-04）

发起者与画师试用第一轮后的结论：

- **穿透意义不大**：钉图不透明，本来就看不到下面的内容。改为一个全局键，把所有钉图**滑到最近的屏幕边**，只留一条细边，并把键盘焦点还给后面的绘画软件；再按一次全部回到原位。
- **不需要 1:1**。
- **钉住选区改用截图的逻辑**：不局限于已收藏的图，网上临时找的参考也能直接钉，目标是**替代 Snipaste**。
- 钉图需要基本操作：缩放带动画，水平／垂直翻转，旋转 90°，调透明度。
- 截图保留一个**历史标签页**（5～10 张，滚动删除），可以一键收藏进资料库；钉图上也提供收藏按钮。

| 操作 | 方式 |
|---|---|
| 截图钉住 | 全局 `F1`：冻结鼠标所在屏幕，拖框选区，然后按 `Enter`／`F3`、双击或点“钉住”。钉图出现在截图的**原位置**。`Ctrl+C` 复制，`Esc`／右键取消 |
| 钉剪贴板 | 全局 `F3`：把剪贴板里的图片钉在鼠标附近 |
| 贴边隐藏 | 全局 `F4`：所有钉图滑到最近的屏幕边，留 6 px 细边；如果焦点在钉图上，会还给之前用的软件。鼠标碰到细边时单张滑出，移开后滑回。再按 `F4` 全部回到原位 |
| 移动／缩放 | 拖动移动；滚轮以鼠标为中心缩放（带动画）；双击回到 100% |
| 翻转／旋转 | 悬停工具栏，或在钉图上按 `H`（水平翻转）、`V`（垂直翻转）、`R`（顺时针旋转 90°） |
| 透明度 | `Ctrl+滚轮`（沿用 Snipaste），10%～100% |
| 锁定／置顶 | 悬停工具栏。锁定后不能移动和缩放 |
| 收藏 | 钉图工具栏的 ★，或截图历史里的“收藏”。原型只把文件复制进 `PROTOTYPE-library` 文件夹，不是正式资料库 |
| 截图历史 | 控制窗口的“截图历史”标签页，保留最近 10 张。滚出的截图文件会被删除，仍被钉住的除外 |
| 重开 | 钉图按原位置、大小、翻转、旋转和透明度恢复，并且处于显示状态 |

全局键会让这些键在所有软件里失效。如果同时开着 Snipaste，`F1`／`F3` 会被先启动的那个占用；被占用的键在“状态”标签页显示为未注册，可以在那里更换。

## 开发机端到端检查（110% 缩放）

`scripts/probe_windows.py` 用模拟的键鼠输入跑完整流程，连续三次 14/14 通过：

- `F1` 约 0.35 秒打开冻结画面（截屏 2560×1440 约 35 ms，写临时 PNG 约 45 ms）。
- 拖框后按 `Enter`：钉图落在选区上（±1 px），截图和 F1 之前的屏幕一致，钉图显示的像素和截图一致；截图进入历史。
- 钉图有焦点时按 `F4`：钉图滑到最近的屏幕边，只露 6 px，键盘焦点回到外部窗口；鼠标碰到细边时滑出，移开后滑回；再按 `F4` 回到原位。
- `H` 翻转后屏幕和镜像截图一致；`R` 旋转后窗口宽高互换。
- 重开后位置、翻转和旋转都恢复。
- 另外单独测过 `F3`：剪贴板里的 200×120 图片被钉住并进入历史。

### 两轮中发现的问题

1. **非整数缩放下的重采样（两轮都遇到）**：canvas 的 CSS 尺寸必须等于“物理像素 ÷ `devicePixelRatio`”，不能用 `100vw` 或整数的 `innerWidth` 推算；100% 时要用 `image-rendering: pixelated`。否则 110% 下细线会变软、1px 网格出现摩尔纹。缩放动画期间先拉伸，停下后再回到精确尺寸。**正式实现要保留这条规则，并做回归测试。**
2. **框选坐标**：鼠标事件的坐标会取整到 CSS 像素，110% 下差 1 个物理像素；改用带小数坐标的 pointer 事件。
3. **贴边后的悬停检测**：6 px 细边在 WebView 里收不到稳定的 mouseenter，改为 Rust 每 60 ms 读一次光标位置。
4. 常驻状态标签会遮住参考图，改为悬停才显示（第一轮）。

## 尚未验证

- 在画师电脑上和优动漫一起用：`F4` 交还焦点后能否马上继续画，`F1`～`F4` 和优动漫的快捷键是否冲突，优动漫全屏时钉图的层序。
- 多显示器：截图只冻结鼠标所在的那块屏幕，贴边按钉图所在屏幕计算，都没有在多屏上跑过。
- 100%／150% 缩放、运行中改缩放。
- 和 Snipaste 的功能差距：标注、取色、长截图、贴图分组等都没有做。
- 截图历史的“收藏”只是复制文件，正式的资料库入库流程（标签、来源）还没设计。

## 画师试用步骤

1. 把 `kinshoko-desktop-pin-prototype.exe` 拷到画师电脑，双击运行；如果开着 Snipaste，先退出它。
2. 在浏览器里找参考图，按 `F1` 框选，按 `Enter` 钉住。再找一两张。
3. 在优动漫里画画。想看画布时按 `F4` 让钉图贴边，确认能直接继续画；鼠标碰一下细边看能否滑出；再按 `F4` 回来。
4. 试滚轮缩放、双击还原、`H` 翻转、`Ctrl+滚轮` 调透明度。
5. 在控制窗口的“截图历史”里收藏一张，关掉原型再打开，确认钉图回到原位。
6. 记下顺手和别扭的地方。可以在“状态”标签页勾选“记录到本地文件”保存操作日志。
