# 桌面钉图原型（PROTOTYPE，#7）

一次性原型，回答 [#7](https://github.com/Yukk1No/kinshoko/issues/7)：画师在实际绘画时，能否清晰、顺手地使用固定局部钉图，并可靠操作置顶、锁定、鼠标穿透与退出？代码不进入正式实现；结论写回 issue。

Tauri 2（WebView2）＋ 原生 JS。数据只写一份 `PROTOTYPE-pins-wipe-me.json`（位于 `%APPDATA%\dev.kinshoko.prototype.desktoppin\`），用来验证“重开恢复”。

## 运行

```bash
npm install
npm run demo        # 开发模式
npm run build       # 生成 src-tauri/target/release/kinshoko-desktop-pin-prototype.exe，可拷到画师电脑
python scripts/probe_windows.py   # 开发机客观检查（会覆盖上面的钉图文件）
```

需要 Rust（MSVC）、Node 22 和 WebView2 运行时（Windows 11 自带）。`python scripts/make_samples.py` 可重新生成自制样本（需要 Pillow）。

## 交互约定（Q64，原型之前先定）

依据[参考板实践调查](../../docs/research/reference-board-practices.md)、[Windows 桌面参考技术核查](https://github.com/Yukk1No/kinshoko/blob/research/windows-reference/docs/research/windows-reference-feasibility.md)和 PureRef 2.0 手册（[窗口模式](https://www.pureref.com/handbook/2.0/features/)、[默认快捷键](https://www.pureref.com/handbook/2.0/shortcuts/all-shortcuts/)）。PureRef 把置顶、鼠标穿透和锁定窗口做成三个独立开关，并建议把穿透快捷键设为系统全局，否则失去焦点后只能从任务栏退出。Kuadro 把锁定和穿透合成一个开关，与领域共识“置顶、锁定与穿透分开”冲突，不采用。

| 操作 | 约定 | 与 PureRef 的差异 |
|---|---|---|
| 打开 | 控制窗口里先选图并框选局部，再点“钉住选区／整图”。每个钉图是独立的无边框窗口，默认置顶、1:1；超过屏幕 60% 才缩小 | PureRef 是整块画布，可另开叠加模式 |
| 置顶 | 每张钉图单独开关，默认开。悬停工具栏或 `Ctrl+Shift+A` | 相同快捷键 |
| 锁定 | 每张单独开关。锁定后拖动、滚轮缩放、1:1 都不生效；系统层面的移动（Win+方向键、贴靠、外部程序）也会被撤回。悬停工具栏或 `Ctrl+L` | PureRef 用 `Ctrl+W`；它在多数软件里表示“关闭”，换成 `Ctrl+L` 避免误关 |
| 穿透 | 每张单独开关：悬停工具栏或 `Ctrl+T`。开启时钉图边缘显示一圈细虚线，提示鼠标和笔会落到下面 | 相同快捷键 |
| 退出穿透 | **全局快捷键**（默认 `Ctrl+Alt+T`，被占用时依次尝试 `Ctrl+Alt+Shift+T`、`Ctrl+Alt+F9`，控制窗口显示实际生效的键，也可以手动换）：有钉图在穿透时，全部退出；没有时，恢复上次穿透的那几张。退出后钉图边缘闪一下确认。另有托盘菜单“恢复交互”和控制窗口按钮 | PureRef 默认不是全局键，需要用户自己设置 |
| 安全规则 | 全局键注册成功前，穿透按钮会拒绝开启；重开应用后穿透一律关闭 | —— |
| 缩放 | 滚轮以中心缩放，经过 1:1 时吸附；按 `1` 回到 1:1。局部边界不变。浏览器自带的 Ctrl 缩放被屏蔽，避免悄悄破坏 1:1 | PureRef 的缩放针对画布 |
| 关闭 | 只能点悬停工具栏的 ✕、控制窗口的“关闭”或托盘“关闭全部钉图”；没有键盘关闭，避免画画时误触 | —— |

1:1 的定义沿用技术核查报告：完成方向校正后，一个原图像素对应一个屏幕**物理**像素。钉图不显示任何常驻信息；状态标签和工具栏只在悬停时出现，按 `D` 显示诊断信息。

全局快捷键会让这个组合键在所有软件里都失效，包括优动漫。如果画师在优动漫里用了 `Ctrl+Alt+T`，需要换一个。

## 开发机客观检查（2026-10-04）

机器：本机 Windows 11，单显示器，系统缩放 **110%**（DPI 106，`devicePixelRatio` 1.104）。`scripts/probe_windows.py` 全部 24 项通过：

- 三张钉图按保存的物理位置和尺寸恢复，都是 `WS_EX_TOPMOST`。
- **1:1 截屏逐像素与原图一致**：像素网格 0/172800 处不同；细线局部 0/126000；EXIF 方向 6 的样本显示为正向，0/120000（JPEG 容差 24/255）。截屏见 `scripts/probe-*-screen.png`。
- 模拟按下全局键后出现 `WS_EX_LAYERED|WS_EX_TRANSPARENT`，`WindowFromPoint` 落到下层窗口；再按一次恢复，钉图重新能收到点击。
- 锁定的钉图被外部 `SetWindowPos` 移动后自动回到原位；未锁定的钉图移动后位置写入文件。
- 重开后位置、裁切、锁定都恢复，穿透关闭（退出前特意留在穿透状态）。
- 另外手测了快捷键冲突：用另一个进程先占住 `Ctrl+Alt+T` 后启动，原型显示失败原因，并改用下一个候选键。

### 原型中发现并修正的问题

1. **110% 缩放下 1:1 被重采样**：第一版把 canvas 的 CSS 尺寸设成 `100vw`，480 个物理像素对应 436.36 个 CSS 像素，合成器重新采样，像素网格出现摩尔纹（172800 个像素中有 153890 个不同）。改成 CSS 尺寸 = 物理尺寸 ÷ `devicePixelRatio`，并在 1:1 时使用 `image-rendering: pixelated`，之后逐像素一致。**正式实现必须保留这条规则，并在非整数缩放下做回归测试。**
2. **常驻状态标签遮住参考像素**（锁定钉图左下角 606 个像素）：改为只在悬停时显示。
3. 穿透时的细虚线边框仍然会盖住边缘 1px，这是有意的取舍，需要画师反馈。

## 尚未验证（需要画师电脑或人工）

- 绘王数位笔在 WinTab 和 Windows Ink 两种模式下能否穿透到优动漫画布，有没有丢首笔或抬笔问题。`WindowFromPoint` 只能证明鼠标命中测试会穿过，不能代替数位板。
- 优动漫全屏时钉图是否仍在上层，Alt+Tab 后的层序。
- 100% 和 150% 缩放下复测（本机只测了 110%）；运行中改变缩放后，物理尺寸是否保持（代码会处理 `ScaleFactorChanged`，但还没有实际跑过）。
- 托盘菜单、悬停工具栏和框选局部只在开发机上粗略看过，还需要画师按约定实际画约 30 分钟。
- 多显示器、混合缩放、其他品牌数位板：按验收约定进入兼容性矩阵，不作首版门槛。
- 内存占用、多窗口资源和无独显表现。

## 画师试用步骤

1. 把 `kinshoko-desktop-pin-prototype.exe` 拷到画师电脑，双击运行（不需要安装）。记下系统缩放比例。
2. 打开优动漫，进入平时的画布（分别试窗口模式和全屏）。
3. 在原型控制窗口里打开自己的参考图，框选 2～3 个局部钉住，摆到合适位置；锁定其中一张。
4. 开启穿透（`Ctrl+T` 或悬停工具栏），用数位笔正常画画；需要调整钉图时按全局键（控制窗口里显示的那个）退出穿透。
5. 分别在绘王驱动的 WinTab 和 Windows Ink 模式下重复第 4 步。
6. 关掉原型再打开，确认钉图回到原位。
7. 逐项记录通过／不通过和感受；可以勾选“记录到本地文件”保存操作日志。
