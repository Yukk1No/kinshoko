# #8 字段保留清单（发起者已评审，2026-10-06）

依据：画师电脑上的真实 Eagle 检查（2026-10-06，Eagle **1.8.2**，300 个条目），以及构造样本的 [RESULTS.md](RESULTS.md)。

**一条总规则**：每个 Eagle 条目的 `metadata.json` 都 **原样整份保存**（`source_binding.raw_item_json`），连 Kinshoko 不认识的字段也保留。下面的“怎么存”一栏写的是在此之外，**另外解析成可查询数据** 的位置。表中所有字段，在真实数据上导入后和备份恢复后都一致。

## 一、Eagle 条目字段

| 字段 | 含义 | 怎么存（除原样 JSON 外） | 她的库里 | 建议 |
|---|---|---|---|---|
| （原文件） | 图片本身 | `originals/<sha 前两位>/<sha>.<ext>`，SHA-256 作身份 | 2126 张 | ✅ 必须 |
| `tags` | 标签 | 来源断言 `assertion(tag)`，可被人工否决或添加 | 80% 有，平均 37.6 个 | ✅ 显示并可检索 |
| `folders` | 所属文件夹 ID | 来源断言 `assertion(folder)` → `folder` 表（保留层级） | 27 个文件夹；28% 的图没有文件夹 | ✅ 显示 |
| `isDeleted` | 在 Eagle 回收站 | 来源状态 `source_binding.state`。**仅首次导入** 时映射成本库的可恢复删除 | 21%（449 张） | ✅ 按已定规则 |
| `name` | 原文件名 | `image.original_name` | — | ✅ 显示在信息栏 |
| `ext` `size` `width` `height` | 格式、字节数、尺寸 | `image` 表各列；`size` 不符时整项失败 | 只有 JPG 和 PNG | ✅ 必须（裁切校验依赖宽高） |
| `annotation` | 整图备注 | 只在原样 JSON 中；显示按第十三轮规则（只有一份备注，与本库备注合并） | 1 张 | ✅ 按已定规则 |
| `url` | 来源链接 | 只在原样 JSON 中；显示按第十三轮规则（链接列表） | 1 张 | ✅ 按已定规则 |
| `comments` | 区域评论 | `region_note`，坐标原样保存，标为“未核验基准” | **0 条** | ⚠️ 保存往返，坐标显示移出首版 |
| `palettes` | Eagle 算出的主色 | 只在原样 JSON 中 | 299/300 有 | 仅保存（①） |
| `modificationTime` | 时间戳（毫秒），推测是条目在 Eagle 中最后改动的时间 | 只在原样 JSON 中 | 全部有 | 收集时间的后备（②） |
| `lastModified` | 时间戳，推测是原文件的修改时间 | 只在原样 JSON 中 | 全部有 | 仅保存 |
| `btime` `mtime` | 推测是文件的创建／修改时间 | 只在原样 JSON 中 | 300 张里只有 1 张有（老条目格式） | `btime` 作收集时间（②） |
| `deletedTime` | 进入回收站的时间 | 只在原样 JSON 中 | 回收站里的图才有 | 首次导入时作删除时间（③） |
| `noThumbnail` | Eagle 没生成缩略图 | 只在原样 JSON 中 | 53/300 | 仅保存（Kinshoko 自己生成缩略图） |
| `id` | Eagle 条目 ID | 来源绑定的外部 ID，用于重导和搬家识别 | — | ✅ 必须 |

## 三、Kinshoko 自己的数据（不来自 Eagle）

下面每一项备份恢复后都 **逐行一致**，参考组 JSON 也逐字一致。

| 数据 | 存在哪里 |
|---|---|
| 人工标签决定（添加／否决） | `manual_decision`；重导从不触碰 |
| 本库备注 | `image.note_manual` |
| 可恢复删除状态 | `image.status` |
| 新旧版本关系 | `image.previous_image_id` |
| 来源登记与状态 | `import_source`、`source_binding` |
| 导入记录与失败原因 | `import_run`、`import_failure` |
| 参考组 | 组 JSON：`name`、`viewport`，以及每个成员的 `member_id`、`source`、`expected_sha256`、`source_size`、`crop`、`x`／`y`／`scale` |
| 恢复来源（新增格式字段） | 组的 `restored_from`、`imported_from_package`，库的 `restore_provenance` 表 |

## 已定

1. **`palettes` 只保存，不解析**。Kinshoko 自己计算主色、按颜色找图，进入 roadmap。
2. **收集时间：优先用 `btime`，没有时用 `modificationTime`**。这两个字段的含义是按名字推测的，没有对照 Eagle 界面核实；发起者接受按此处理。规格里注明这一点；以后发现不对，只需要改映射，原样 JSON 都还在。
3. **`deletedTime`**：首次导入时，Eagle 回收站里的图进入本库的可恢复删除，删除时间用 `deletedTime`。没有这个字段时，用导入时间。

## 版本

画师用的 Eagle 是 **1.8.2**（已确认），字段结构与公开的 4.0 格式基本一致，全部门槛都通过了。正式规格：

- **不按 `applicationVersion` 拒绝导入**，按字段是否存在来解析；
- **首版明确支持 Eagle 1.8.x 与 4.x**；
- 遇到未知字段照样原样保存；缺少必需字段时，该项按失败处理并给出原因。
