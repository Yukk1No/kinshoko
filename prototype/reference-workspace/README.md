# Reference workspace prototype

一次性的交互试验：哪种任务组织方式能让画师更快找到、取用并再次使用参考？与 `library-browser` 样稿独立，保留旧样稿作比较。这里的代码不直接作为正式应用起点。

```powershell
pnpm install --frozen-lockfile
pnpm demo
```

打开 `http://127.0.0.1:4176/?variant=A`，或在已有开发服务器下使用 `/prototype/reference-workspace?variant=A`。底部切换 A / B / C；找图页面的背景获得焦点时也可用左右方向键。取用、绘画参考、参考组页面，以及输入框、图片墙和弹窗保留自己的按键。显式的 `pnpm build:demo` 保留方案切换器，普通 `pnpm build` 隐藏它。

| 方案 | 任务组织 | 试用问题 |
| --- | --- | --- |
| A 专注取用 | 找图 → 取用 → 绘画参考，每次一个完整视图 | 阶段切换能否降低信息负担？ |
| B 查找台 | 图片墙 + 本次参考托盘，取用时聚焦原图 | 是否方便持续比较、累积参考？ |
| C 并排工作台 | 资料墙与参考区同时展示；手机按任务切换 | 是否值得牺牲一些图片墙宽度？ |

## 领域关系

资料库拥有原图及元数据。文件夹是可分层的组织方式；一张图可属于多个文件夹，列表计数按图去重。标签描述图像特征，文字词项与点击的标签同时满足。常用查找保存范围与条件，重新打开时按当前资料查找。独立参考组保存来源引用、局部范围、摆放位置与叠放顺序，可跨资料库取用；保存组不复制原图。

文件夹默认包含后代，可以切成仅本层。这个规则与三种布局都是交互假设，未改写领域 ADR。局部范围在取用阶段确定，参考窗口只提供移动、缩放显示和位置锁定。

## 一次完整试用

1. 选择「角色创作」，切换是否包含子文件夹；回到全库，点击「人像」「长发」，或输入「长发」。
2. 点图，选择整图或局部；在图上拖出局部，或输入百分比范围。加入后继续找图，检查条件仍在。
3. 切到「显示测试」资料库，再取一张图。原来的参考应仍保留。
4. 在绘画参考区拖动标题、锁定位置、调整显示大小，保存参考组。
5. 从侧栏打开参考组列表，再打开刚保存的组，检查取用范围、顺序和位置。
6. 在原图详情中同时勾选两个文件夹，返回浏览，检查同一张图可在两处找到。可以新建文件夹或保存一条常用查找。

## 范围

全部状态只存在内存，刷新即重置。可选择本地 JPEG / PNG / WebP，不上传文件。公开作品与原有几何样本沿用旧样稿，来源见 `../library-browser/public/samples/SOURCES.md`（Vite 共用旧样稿的 public 目录），标签人工编写，不验证动漫自动打标的准确率。浏览器中的参考窗口仅模拟桌面置顶；未验证 Tauri、DPI / ICC、备份、同步或持久化格式。列表复用旧样稿已经验证过的 TanStack Virtual 瀑布流，仅增加窄屏两列规则，不把样本数量当性能基准。
